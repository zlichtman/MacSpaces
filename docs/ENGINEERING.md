# MacSpaces engineering guide

MacSpaces is a native macOS menu-bar app built around the **Nook**: a panel that opens from the physical camera notch, or a synthetic notch on other displays, with a dock of full pages, a Home grid of widgets, a file Tray, compact live activities beside the closed notch and cards under it.

- The version and build live in `project.yml` (and `RELEASE_NOTES.md`). `README.md` is the public page, `Demos/README.md` describes the README images, and this guide is the current state. Agent rules are in `AGENTS.md`.

## Code layout

- `Sources/Core`: pure catalogs and logic: feature catalog and dependency-aware service lifecycle (`Features`), action registry (`Actions`), `CompletedFileTracker` (`Files`), playback capabilities (`Media`), `NoteRepository`. `FeatureCatalog` keeps only shipped features and the fields `NookWidgetKind` reads (title, symbol, summary, permissions, width, compact).
- `Sources/App`: entry, menu-bar menu, `AppServices` (service demand), `ModuleCoordinator` (creates only `NotchManager`), updates.
- `Sources/Modules/Notch`: `Core` (display geometry, per-display windows, hover, collapse/expand, sizing), `UI` (panel shape, dock, live activities, transitions), `Features/Widgets` (Home dashboard and widget views), `Settings` (`NookSettings`, `WidgetOptions`, the General/Notch/Files panes).
- `Sources/Modules/{Actions, Clipboard, Converter, Meetings, Prompter, Voice}`: Find Action, App Intents and Finder Services; the clipboard popup; File Converter and File Tools; meeting controls; teleprompter; dictation.
- `Sources/Services`: media, lyrics, weather, calendar, clipboard, timers, coding stats, updates and other services. `PowerHelperProtocol.swift` is shared with the helper.
- `Sources/DesignSystem`: themes, `Design` motion tokens (open/close/hover springs, `nookDepth` transitions), optional trackpad `Haptics`, `OlderMacOS.swift` stand-ins, `RefreshButton` (its arrow turns once per click). All motion honours Reduce Motion (system or the app's own).
- `Sources/Settings`: the Settings window, search index, Home layout editor and inline sample widget gallery, Clipboard preferences.
- `Sources/Debug`: Debug-only QA harnesses, regression checks and website capture.
- `Helpers/PowerHelper`: the privileged helper. `Tests/`: sources for `Scripts/check-*.sh`.
- Shared keys: `WidgetOptions.Keys` (no repeated key strings).

## Compatibility

- Swift 5.9; macOS 13 deployment target; universal (arm64 and x86_64). `project.yml` is the project definition (XcodeGen); the generated Xcode project is ignored. iCloud conflict copies `Sources/Resources/Info *.plist` are ignored by Git and excluded from the project.
- Anything newer than macOS 13 needs `#available` with a fallback. Shared stand-ins live in `OlderMacOS.swift` (`refreshTurn`, `scrollContentTopMargin`, `textFieldKeys`, `NoSearchResultsView`); `onChange` uses the one-value form; EventKit `.fullAccess` is checked with `#available` (`.authorized` before 14).
- Before macOS 14 the Settings search and the Terminal prompt line handle Escape but not ↑/↓, and the refresh arrow uses a plain rotation.
- macOS 14+-only features (listed in README Requirements): Tray Remove Background, Continuity Camera/Desk View in Mirror, ↑/↓ in Settings search and the Terminal prompt line.
- Use explicit captures in nested actor closures (the CI compiler requires it). Locks used from async code are `OSAllocatedUnfairLock`, not `NSLock`.
- Animated views use timer-scheduled (`.periodic`) TimelineViews, not `.animation` schedules, which pause when macOS reports the menu-bar panel as hidden. Avoid `rotation3DEffect` spins (they vanish edge-on and look flat); scale x instead.
- Timers schedule in `.common` run-loop modes so they move while a menu is open.

## Nook shell

- **Geometry**: app pages share a 620×346 base, clamped to the display; Home follows its widgets (legacy manual sizing preferences are kept but don't control geometry). Content starts below the physical camera; a detached dock sits below the panel and the shared hover region includes the gap. AppKit owns window geometry (SwiftUI size propagation is isolated).
  - **The camera**: `NotchGeometry.resolve` turns what a screen reports (`safeAreaInsets.top`, the auxiliary top areas' widths, the menu bar's height) into the closed surface. A notch spans the gap between the auxiliary areas, the inset tall; a screen without an inset gets the synthetic pill (144/156/168 pt by width, 30 tall).
  - **The island** (MacBook Pro with PROLED XDR display, from October 2026): its camera is an oval cutout below the top edge. The built-in display is taken to have it when macOS 27's `NSScreen.touchCapabilities` is non-empty (the only touch Mac display; read through KVC so SDKs without it build and older systems say no). Apple publishes no cutout size or API, so the capsule comes from the best thing known: a measured cutout plus a 1 pt bleed (`Reading.islandCutout`, only Debug captures set it), else the band macOS keeps clear (the auxiliary gap, the inset tall, from the top edge), else a stand-in centred in the menu bar (its height less 6 pt, 3.4× as wide). The closed capsule stays centred on the cutout as it peeks, swells for a file or grows to 26 pt for lanes (`closedTopPadding`), its radius half its height. It opens as on a notch Mac: the panel hangs `cameraGap` below the cutout (`expandedPanelTopPadding`, from `cameraBottom`; pages are `topInset` taller so content keeps its room) and closes back up into the capsule. The island itself is left to macOS 27, which shows its own Dynamic Island there (Spotlight, Siri, Live Activities): while the Nook is open nothing is drawn over it and the whole band down to the panel passes clicks and touches through (`expandedShoulderClearance`). Closed, the capsule's hover area reaches up to the top edge; the agent bubble sits beside the capsule at its height, and the teleprompter hangs below `cameraBottom`. Notched and notchless Macs take none of these paths (`isIsland` false, `topInset` 0).
  - **One model, two switches**: `NotchGeometry` is the cutout (`Cutout`: `.notch`, `.island`, `.none`) plus how the closed Nook draws around it. `look` is `.solid` (default: the black notch, capsule or pill with lanes) or `.clear` (the surface over the camera is invisible, `clearHitOpacity` so it still catches the pointer, and turns solid while peeking or taking a file; each activity is a `NotchBubble`, the agent bubble's size, first left of the camera and second right (a song alone is a pair: its cover left in a `squircle` bubble, a continuous-corner square like an album cover, filled by the art; its sound right, bars in a black squircle of the same shape, coloured with the cover's strongest colour (`ArtworkWashStore.tint`, from `CustomTheme.palette`) or the theme's accents; everything else, the agent bubble included, is a black circle with no outline at rest, a timer keeping its countdown as a thin arc in its colour), lanes `AgentPopoutLayout.laneWidth` wide so the agent bubble continues the row). `notchlessHint` shows the clear look's resting pill at `notchlessHintOpacity` on screens without a camera. `outline(expanded:surfaceHeight:)` picks the shape: a solid notch or pill keeps its ears and inward-rounded panel; everything else is the capsule family, opening into the same panel through one animatable path (radii and side inset). Both are Settings → Activities → Look (`NookSettings.notchLook`, `notchlessHint`, stored under `NotchGeometry.lookKey`/`notchlessHintKey`); `NotchGeometry.detect` reads them and `NotchManager` rebuilds the windows when either changes.
- **Opening**: click always opens; hover, scroll-down and file drags are optional (General → Open & close). File drags open Tray only after pausing near the closed notch. Hover and scroll open only with the pointer on the closed notch itself (`NotchViewModel.isPointerOnClosedNotch`, the notch plus its hover peek); SwiftUI can report hover where the open panel was while it closes, so a hover that starts elsewhere waits for the pointer to reach the notch. Hover and scroll never open the Nook while Mission Control or App Exposé shows (`MissionControl.isActive`), and an open Nook checks about three times a second and closes when Mission Control appears.
- **Performance**: `MissionControl.isActive()` coalesces background WindowServer queries; hover/scroll requests validate their request ID after awaiting. `MotifImages` retains the selected scene, decoded off-main. Decorative motion waits for opening. Closed-lane observations stay in `CollapsedNotchContent`; only settings/lane geometry can resize the host. Statistics, agent scans and Tray metadata run on bounded workers, publishing only current results. `ArtworkWashStore` prepares washes off-main with one reusable Core Image context. The shell's surface tint is a plain gradient under the panel's clip (a gradient-filled animating shape was redrawn by Core Graphics every frame). The microphone/Focus monitor reads CoreAudio and Focus on a utility queue: CoreAudio listeners (default input, its mute and volume) trigger a microphone read when it changes, and a 0.45 s timer reads Focus alone, which has no notification. Covers from every player are decoded once off the main thread and scaled to `NowPlayingInfo.coverPixels` (640), so looks, washes and caches never hold the original art; the cover caches are bounded. Mood's sentiment and Scenes' catalog matches for a song are made off-main when its lyrics load, as are LRCLIB decoding, matching and LRC parsing. The clipboard popup draws clip images from a per-clip thumbnail cache (`ClipThumbnails`). Repeating timers run in `.common` modes (all but the Converter wheel's and the Teleprompter's, which `Scripts/check-timers.sh` lists) and polled values publish only when they change. The scrubber is its own small view on a quarter-second timeline. Live flower scenes run in Core Animation (`FloralLayerScene`: the photo drifts by a layer animation, motes come from emitters), so the app does nothing per frame; other effects draw on a timeline.
- **Hide in apps** (`NookSettings.hiddenInApps`, General): windows are ordered out while one of those apps is frontmost, and the rule is applied when windows are built (`HiddenApps`).
- **Keyboard**: a closed Nook hands the keyboard back (`NotchManager` reorders a key `NotchWindow` on collapse). Widget keys (Delete, ⌘Z, Escape) are ignored while any text input has focus. Keyboard-opened pages stay open until closed.
- **Dock**, three capsules; long lists scroll inside their capsule:
  - App pages (`NookSettings.dockApps`, chosen and reordered in Settings → Notch → Apps by the ☰ handle, `DockAppsCard`), Home always last. File drops open Tray even when it isn't in the dock.
  - Controls for the active page: on Home one button per profile (`NookProfile.symbol`, shown only with two or more profiles); on Music the playlist (playlist order), only while Apple Music is the source; other players leave no empty capsule; on Wisp the Answer out loud toggle (`wispSpeaks`), lit like the current profile while on.
  - Settings, with optional Pin and Close beside it (`showDockPin`, `showDockClose`, default and reset on), switched together under Settings → Apps → Dock → Next to Settings.
  - Fresh install and Reset: `NotchTab.defaultDock` (Music, Weather, Calendar, Clock, System, Terminal, Tray, Timers, Mirror, Meetings, Dictation); Wisp is offered under More pages, never added on its own. Installs with saved profiles but no saved dock keep `NotchTab.legacyDock`. Meetings/Dictation and Clock were appended once to saved docks (`dock.communicationPagesAdded`, `dock.clockPageAdded`), later removal persists. 3.31–3.34 added Wisp the same way (`dock.wispPageAdded`); a dock that still has it from that loses it once (`dock.wispPageWithdrawn`), nothing else moving, unless `wisp.enabled` was stored true (turned back on by hand). Wisp is on exactly when its page is in the dock: a stored `wisp.enabled` of false (Wisp's old switch) removes the page once, and the key is then deleted so adding the page back sticks; a stored `wisp.dockButton` is ignored. Saved docks drop retired pages on decode.
- **Home**:
  - `NookWidgetKind` is the widget catalog; its cases drive the library, persistence and view factory, and new cases need a title, symbol and sizing. Menus list widgets alphabetically (`NookWidgetKind.alphabetical`); Add Widgets groups come from `NookWidgetKind.libraryGroups`, which must list every widget. Saved profiles drop removed widgets and style fields on decode.
  - Fresh Home (profile “Home”): Music (large), Timer, regular Clock (`starterWidgets`, `starterSizes`).
  - Each widget uses one canonical size (`defaultSize`); legacy saved size fields decode but do not control layout. Music is large; Clock, timers, Battery and Keep Awake are compact. Adjacent compact widgets stack, oversized profiles scroll, and the empty profile opens the visual gallery. Tiles have no header (VoiceOver names them).
  - Clicking selects (accent outline); Delete/Forward Delete removes; ⌘Z or the Undo bar restores in place for six seconds; Escape deselects.
- **Widgets and pages are one feature at two sizes**: `NookWidgetKind.page` names the page behind a widget (nil for Calculator); the tile's corner button, double-click or "Open …" calls `NotchViewModel.openPage(for:from:)`, which records `pageAnchor` so the page scales out of the tile. Shared pieces live once (`ClipListRow`, `ClipMenu`).
  - Open work: share Calendar/Reminders rows, make each page the feature at page size, then merge `NotchTab` into the feature catalog with a saved-dock migration.
- **Mirror**: one shared camera controller retains one session and serial worker queue across visits and displays. Device discovery/configuration stay off-main and discovery is cached for 30 seconds or until a device change. Opening the Nook can preconfigure an already-authorized camera when Mirror is in the dock; capture starts only with a visible Mirror. Readiness waits for a video frame, interruptions and runtime failures recover or offer retry, and outgoing previews detach synchronously before panel/page transitions. Preview layer updates disable implicit animations. Camera permission remains an explicit button action. The chosen camera (`preferredCameraID`, `mirror.selectedCameraID`) is kept while it's unplugged: Mirror skips disconnected devices, replaces a dead input, falls back to the built-in camera first, looks again 1.2 s after a device change, and returns to the chosen camera when it's back.
- **Service demand** follows enabled widgets and visible pages; a closed page's services keep running four seconds (`lingeringTabs`); safe dock services warm during hover and while open, Music takes a passive system metadata snapshot without AppleScript, page startup reconciles on the next run-loop turn, and stopped work rejects late generations.
- **Closed notch** (live activities): music bars, every running timer in its colour, the meeting countdown, power, paste-queue count, new-screenshot thumbnail, microphone mute, Focus and Keep Awake, each toggled on Settings → Activities → Beside the notch.
  - Keep Awake (`CollapsedActivityKind.keepAwake`, after the song in priority; `showKeepAwakeLiveActivity`, on for new installs and off for installs that already had a stored dock): the widget's `cup.and.saucer.fill` in the accent, with the time left beside it when it has a limit (`KeepAwakeService.expiresAt`). With no limit it is the cup alone and the right lane is empty. The clear look's bubble is the cup, with a thin accent arc of the time left (`KeepAwakeService.duration`) when limited. The countdown is a `TimelineView` on `KeepAwakeCountdown`, which yields a date only when the label changes: each second under an hour ("42:07"), each minute over it ("1h 05m"), none after the end. Feature QA `notch-looks` captures it alone, without a limit and beside a timer (`looks/<cutout>-<look>-awake*.png`).
  - Arriving and leaving: an activity slides out from under the camera and leaving slides back under it, the reverse, on one curve (`Design.laneAnimation`, 0.34 s; leaving is the arrival's curve mirrored), never fading or shrinking. Each side is a `TuckedActivity`, moved by its own state rather than a SwiftUI transition (a view being removed keeps its old place, so a transition only faded it where it sat); an activity being replaced tucks away before the next comes out, and one that stays changes in place. The clear look's bubbles sit in fixed slots placed on the camera (outside the surface, which shifts and resizes), each sliding its slot's width; the solid look's lane content rides its black edge in as the surface draws in. `CameraEdgeMask` hides what crosses a lane's camera-side edge, so it tucks under the hardware, an island's capsule or a notchless pill alike. `CollapsedNotchContent` sets `NotchViewModel.shownActivities` on the same curve, so the shell's surface and offset follow without observing the services. Empty lanes keep their last measured width, so the next activity starts from the camera. Reduce Motion: a plain fade. Feature QA `bubble-exit` captures it frame by frame.
  - Opening and closing beside them: the open surface drops from the closed surface and then widens (`Design.openDownAnimation`, `openOutAnimation`), and closing draws in and then rises (`closeInAnimation`, `closeUpAnimation`), so it never sweeps sideways over the lanes. The solid look starts from its lanes, whose content rides the black. The clear look draws only on the camera's outline (`NotchContainerView.drawsOnCamera`): closed, its lanes only catch the pointer (an invisible fill at `clearHitOpacity`) and the hover peek grows down alone while bubbles are out; opening, the bubbles tuck under the camera (`Design.bubbleTuckAnimation`, 0.16 s, `TuckedActivity.held`) as the panel drops from the camera's outline beside them, and it widens once they've gone (`openOutAnimation(afterBubbles:)`), so nothing filled shows where they were until the widening passes there; closing is the reverse: in and up to the camera's outline, solid until it's there (`Design.closeSettle`), then the bubbles slide out (`bubblesOut`). A file swelling the notch still grows from the lanes. Reduce Motion: both directions together, the bubbles fading. Feature QA `open-morph` captures it frame by frame, and `open-morph-song` the song alone after a hover peek, before and after (`open-morph/song/`).
  - Lanes fit their content (`LaneWidthKey` → `NotchViewModel.measuredLaneContent`): both lanes take the wider side (minimum 36 pt) with 10 pt on the outer side and 4 pt beside the camera; power and system cards keep fixed lanes. Power feedback precedes routine system-control feedback.
- **Agent pop-out** (`AgentPopout`, pure placement and visibility in `AgentPopoutLayout`, state in `AgentFace`): a round bubble `AgentPopoutLayout.gap` shorter than the closed notch (`bubbleSide`), sitting that gap below the top edge and level with the notch's bottom, slides out `AgentPopoutLayout.gap` (2 pt, the clear look's bubbles too) right of the closed notch and its lanes (`NotchViewModel.closedNotchFrame`, via `NotchManager.agentAnchor()`), on the notched display, showing the agent's own app icon (`AgentActivityMonitor.agentIcon`: Claude's app for Claude Code, the Codex app, which ships as ChatGPT, for Codex; else the app the session runs in; else Terminal's; never a stand-in symbol, the tick for a finished session sitting on that session's icon). While a coding agent needs you its accent ring breathes (`AgentPopoutLayout.pulse`, 1.6 s), with a count for two or more. With Settings → Activities → Show the bubble while agents work (`agentActivity.peekWhileWorking`, off unless chosen, as before the setting existed) it also shows while a session works (the newest working session's icon, the ring fainter and slower) and shows a green tick for `AgentFace.cheerDuration` (4 s) when one goes from working or waiting to done (`AgentPopout` compares each scan's states). Waiting beats a tick, which beats working (`AgentFace.mood`). The ring breathes as one repeating Core Animation group on its layer (`AgentPulseRing`, per mood), so the app does nothing per frame; Reduce Motion holds the ring still. It's a non-activating `.statusBar` panel with `sharingType = .none`; it hides while the Mac is locked, a Hide in app is in front or that Nook is open, and moves when the notch's lanes change (`NotchManager` calls `refresh()`), sliding with the row on its curve (`Design.laneTimingFunction`; under Reduce Motion it fades out and back in). Clicking opens the Terminal page's Agents tab with the waiting session (else the newest working one) outlined, pinned (`NotchManager.openAgents(session:)`, `AgentActivityMonitor.spotlight`); its menu also goes to the agent's app. The notch's hover check skips the bubble. Nothing drops down under the notch: notification cards and the reader of Notification Center's store were removed.
- **Menu-bar menu**: Open Nook, Find Action (with its hot key), Enable Nook, File Converter ▸ (Convert by Shift-Dragging, Open File Tools), File Baskets │ Settings │ Check for Updates │ Quit MacSpaces. No ellipses.
- **Find Action** (`ActionSearchWindow`, default ⌃⌥Space, set in General → Keyboard) searches MacSpaces actions and Apple Shortcuts, not apps or files. Optional direct page shortcuts (⌃⌥N Home, T Tray, M Music, K Terminal, D Dictation).
- **App Intents** (`MacSpacesIntents.swift`): open a Nook page, stage files in the Tray, convert files and return the results. **Finder Services** (`project.yml` NSServices): Add to MacSpaces Tray, MacSpaces File Tools.

## Settings

- Pages, in order (`SettingsDestination`), under three non-collapsing sidebar labels (`SettingsDestination.section`); there is no About page:
  - **Core** section:
    - **General**: updates with the version first, then startup, displays, open & close, keyboard, hide in apps and reset.
    - **Appearance**: theme drawers (closed on entry), Lyrics, Album covers (Show covers and lyrics from your local music files, off by default), Motion.
    - **Permissions** (`WidgetAccessSettings`): each permission's live status, re-read every 2 s while open; opening it requests nothing, and a row's Allow or Open Settings button asks or opens System Settings.
  - **Notch** section:
    - **Home** (case `widgets`, `NookSettingsPane`): compact profiles, visual layout with inline removal and drag reordering, and an inline widget gallery. Gallery previews use sample content and start no services; the starter previews share the real Music, Clock and Timer components, and each gallery row fills its width. Typed `dev.opensource.MacSpaces.widget` drops add into the layout or native Nook; a drag temporarily pins Home, restored on finish/cancel. Selecting a layout preview gives it keyboard focus: Delete/Forward Delete removes it and Escape deselects; keys in text fields keep editing text.
    - **Apps** (case `apps`): the Dock card; page-specific controls stay on their pages (`DockAppsCard`); unused pages are alphabetical.
    - **Activities** (case `activities`, `ActivitiesSettingsPane`): Beside the notch, including Coding agents that need you (the agent pop-out).
  - **Tools** section:
    - **Files**: Screenshots, Downloads & folders, File Converter.
    - **Clipboard**, including Keep history after quitting.
- `SettingsSearch.entries` indexes every card (⌘F); add an entry for each new card. Settings remember the current destination, and Nook shortcuts open the relevant page.
- The window can grow but not shrink below 980×680 (less only on a short screen); tiling that squashes it is undone. Content scrolls under the title bar with a fade; the sidebar marks the selection with its highlight only.
- Settings shows only the version (the build appears on hover).
- **Controls** (`SettingsControls.swift`, in the theme's `ThemeStore.settings` colours): every page uses the same few. Search is `SettingsSearchField` (magnifying glass, plain field and clear button in a 34-pt capsule that brightens while focused): the sidebar passes its own field for its keys and focus, and lists inside cards ("Search widgets", "Search terminal themes") use `SettingsListSearchField`. Buttons use `.buttonStyle(.settings(role))`, all 28 pt high with 8-pt corners and dimmed while disabled: `.primary` (the accent, text black or white by contrast, `ThemeStore.settingsOnAccent`; at most one per card: Install when an update is waiting, Choose Picture), `.secondary` (a faint fill: Check Now, Add, Add App, Choose Folder, Allow, Open File Tools, Change Picture), `.quiet` (accent text: Refresh, Reset) and `.destructive` (red: Remove Picture, Reset all Nook settings). Removing one item from a list (an app, a folder, a pattern or format) is `SettingsRemoveButton`, a minus that turns red on hover. Chips (Home profiles, Custom's styles) use `SettingsChipStyle` and two-to-four-way choices (Displays, Closed notch) `SettingsSegmentedPicker`, both on `SettingsChipBackground`: the selection tint with an accent edge when chosen, a faint fill otherwise. Text fields use `.settingsTextField()` (a faint fill and hairline at button height). Toggles, pop-up menus, sliders, colour wells, alerts and `NSOpenPanel` stay native, labels on the left. Button and menu labels read plainly, with no trailing "…" (a progress line such as "Loading…" or a field's placeholder keeps its own). A Settings control's open panel goes through `SettingsWindowController.runPanel`: a sheet on the Settings window while it's open (an app-modal panel otherwise), after which MacSpaces activates and Settings becomes key again (`refront`, now and on the next run-loop turn), because an LSUIElement app has no Dock icon and macOS can hand the front to another app's window when a panel or privacy prompt closes. Exceptions: the Terminal drawer's Dark/Light filter is still a native segmented picker, and Nook previews inside Settings (layout tiles, gallery cards, lyric and theme previews) keep the Nook's own look.

## Features by area

### Music and lyrics
- Lyrics show only on the Music page and advance only while it's visible; lookups may start while the Nook opens (`TeleprompterService.prefetch`, from `AppServices.prewarmDockPages` with Music in the dock and the player already being read). The Media widget mirrors the page (slim scrubber, no artwork wash) without lyrics.
- `LyricStyle`: Classic, Poster, Mood, Choreography, Scenes (saved as `stickers`), Karaoke, Typewriter, Cinema, Departure. Poster is the default. Settings → Appearance → Lyrics (`LyricStylePicker`) is a list of the styles beside one large preview: hovering a name previews that style without choosing it, clicking chooses it (accent highlight and a check), and the preview plays three synthetic lines on a loop only while hovered (static otherwise and under Reduce Motion, and stopped when Settings is inactive). Styles use the theme's accent and ink (Mood also takes the album cover's colours; Scenes' stickers keep Fluent Emoji's own colours); motion stops under Reduce Motion (system or the app's own). Retired styles read back as Classic.
  - Every line change, a repeated line included, has its own `TeleprompterService.lineID`; styles key their entrance on it. The shared handover is a 0.18 s fade.
  - Poster sets the longest word (filler such as "something" excepted) as a condensed headline; supporting text keeps a readable floor (11–13 pt). Each line keeps its own composition (`PosterLyric.composition(for:)`): mostly left-aligned, flush right only for short lines. Short tails sit beside the headline at its natural width; longer phrases stack below. Words before the headline are always in the italic serif voice at near-full ink (never a pale tracked caption).
  - Mood = Poster over a lyric-video backdrop, one treatment per line (`MoodTreatment`, pure, in `Sources/Core/Media/MoodTreatment.swift`): Sweep for one or two words, or three with clear feeling; otherwise feeling picks the family and pace (words a second over the line's `lineSpan`; slow under 1.6, fast from 3.2) the member: sad lines are Haze when slow, Rain otherwise; warm lines Bloom, or Embers when fast; plain lines Drift when slow, Aurora at a medium pace, Pulse when fast. Untimed lyrics count as medium pace (2.2); the pace also sets the tempo (0.75–1.35×) and how hard the line lands (`hitStrength`). Feeling is `NLTagger`'s `.sentimentScore`, re-centred because the model scores plain lyric lines about -0.5 (`MoodTreatment.calibrated`, with a short list of sad words that tips a line to Rain), cached per line text (`MoodSentiment`).
  - Each scene (`MoodScene`) has three depths: a slow field of two colours wandering and breathing at the back, the treatment's motif in the middle (motes, rings, glows, two depths of rain, ribbons, embers, fog banks), and near sparks plus a light film grain (a fixed noise image jumping between offsets 12 times a second) in front, all faded toward the lyric area's edges. Each line adds beats (`MoodScene.beats`): a soft hit at the first word, scaled by pace, and an accent per word as it's sung (a ring, a splash, a flare, a gust or a burst of motes; the headline's is the biggest, behind it). Word onsets spread the line's sung 85% by syllables (`wordOnsets`, `wordDelays`, from `TeleprompterService.lineSpan` and the song's time as the line renders); untimed lyrics get only the hit. The poster keeps a soft shadow for contrast.
  - Colours: Mood is the one style that also takes the album cover's colours. `MoodCoverPalette` reads two hues (the strongest and a distinct second) from the Music page's own blurred cover (`ArtworkWashStore`) on a utility queue, keeping the last few; `MoodPalette` makes them vivid enough for the surface, leans them toward the theme's accent and uses them with the accent and ink. With no cover (or a grey one) the accent stands in, so MacSpaces' white accent still reads.
  - Live, every element is one Core Animation animation in the window server (`MoodLayerScene`, nothing per frame in the app); beats begin at times from the line's timing, and everything holds while the song is paused. The same scene is drawn in SwiftUI at a fixed moment (`MoodFrame`) for Settings previews, Reduce Motion (no beats) and captures. A changed treatment (or cover) crossfades over 0.9 s; the same treatment carries on across lines.
  - Cinema and Departure (`CinemaLyric`, `DepartureLyric`, sharing `LyricTypographyStage`): Cinema centres a serif line between fine widescreen rules with the upcoming line beneath and a slow push-in paced to the span; Departure sets the line in capitals on split-flap plates that turn over in a short cascade paced to the line. Both use finite Core Animation keyed by line, hold on pause and show the settled composition under Reduce Motion.
  - Scenes (`stickers`) = Poster + one Microsoft Fluent Emoji (MIT) for what the line is clearly about, in a square beside the headline with its whole frame reserved (left of a flush-right poster). `StickerChoice` (cached per line text) picks it with `StickerMatch` (pure, in `Sources/Core/Media/StickerMatch.swift`) over the whole bundled catalog (`Sources/Resources/sticker-index.json`, 1,364 emoji with names, groups, keywords and file paths, 736 animated; regenerate with `Scripts/build-sticker-index.py`). Better none than wrong:
    - Curated subjects first (`LyricSubject`, pure, in `Sources/Core/Media/LyricSubject.swift`; 31 subjects with slang and context rules: lean/sip → cup, racks/bands → money, whip → car, ice/drip → gem, a broken heart needs "heart" and a breaking word within three words, coffee cups, bike chains and book clubs stay out). ### Clipboard
- History is memory-only unless Keep history after quitting is on; it excludes concealed/transient types and text shaped like a credential (`ClipboardSecrets`: private keys, prefixed tokens, JWTs, Luhn card numbers, `.env` blocks).
- Kept history, `clipboard-pins.json` and `scripts.json` are sealed by `SecureStorage` (AES-GCM, "MSE1" header; key via HKDF from a Secure Enclave P-256 agreement, or a keychain key without an enclave; `storage-key.json` 0600). Older plaintext files are read and re-sealed.
- Popup (`ClipboardPopup`, Carbon hot key `ClipboardPreferences.shortcut`, default ⇧⌘C, no permission): a non-activating key panel at the pointer, centre or under the notch with Maccy-style keys (↩ copy, ⌥↩ paste, ⌥⇧↩ plain text, ⌘/⌥1–9, ⌥P pin, ⌥⌫ delete, ⌥⌘⌫ clear). Pasting reactivates the previous app and posts ⌘V (Accessibility, asked on first use; otherwise clips are only copied). The shortcut keeps the clipboard service running.
- `ClipboardPreferences` (Settings → Clipboard): history size (default 200, up to 1,000), sort, search mode (exact, fuzzy, regex, mixed), pins position, preview, pause/ignore-next, clear options, auto-delete, and `ClipboardFilter` (kinds, apps, regex, pasteboard types).
- Entries carry `firstDate`, `copyCount` and `recognizedText` (Vision OCR on image clips, off the main thread); `ClipboardQuery` parses `@kind`, `@app`, `#collection`. Snippets, collections, pin keys ⌃A… (no N, P, U), drag out, colour picking, `ClipMenu` shared by popup, page and widget. `MaccyImport` reads Maccy's Storage.sqlite read-only, applying credential, app and private-type filters.
- Paste queue (off by default): each ⌘V or ⌥⇧⌘V puts the next clip on the clipboard 0.2 s later, in order or newest first. Seeing ⌘V elsewhere needs Accessibility, requested only when turned on. The closed notch shows only a count; turning it off puts the last copy back.
- Pin letters (⌃A…, no N/P/U) are stored on each pin (`pinKey`) and kept while it stays pinned; new pins take the first free letter, and Maccy imports keep Maccy's letter when it's free. The popup follows `monitor.entries` while open (right-click actions, new copies and OCR show at once; the selection is kept by id). ⌥↩ pastes into the app that was in front when the popup opened, and only copies if that was MacSpaces. ⌘V is sent with the key that types "v" in the current layout.
- Maccy import (first in Settings → Clipboard) reads and filters off the main thread, merges by date (newer clips here are never pushed out; existing dates aren't made older), reports what was kept after the history-size and 50-pin limits, and tells "nothing to import" apart from "couldn't read". Auto-delete runs at launch, when its setting changes, after an import and on each copy. OCR runs one image at a time on a bounded worker, newest first, and drops results for deleted clips. Settings shows storage errors under Keep history after quitting. `SecureStorage` never replaces a storage key it can't read (file or keychain): saving fails closed and the key is kept.

### System page and the power helper
- System stats (`SystemStatsWidget(detailed:)`): CPU, memory and network graphs (network scaled to its own peak), memory used, swap, free disk, load, uptime, thermal state.
- The page is 860 wide with three untitled sections: System stats | Overtime | power (`CableManagementCard`), with `BatteryPill` spanning the last two underneath (`SystemAppView`). `PageCard` titles are optional; the Shortcuts page still uses them.
- Overtime (`OvertimeCard`): Low battery (`AgentPowerAlert`, 20%: hooks tell Claude Code and Codex sessions to save and commit), Agents keep running (`LidClosedAwake`), Keep awake (durations and a display chip in one row).
- Alignment: the power column's rows (`PowerRow`) use Overtime's row metrics (30 pt icon circle, 10 pt gap, 6 pt vertical padding), so the two columns line up row for row. `BatteryPill` is 44 pt tall with a 9 pt bottom inset, matching the stats graph block; its left edge is the row icons', its terminal the switches' right edge, the bolt centred in the icon column, the level at the titles (40 pt) and the time at the power column's titles (`timeInset`). Its fill is the tint at 38% so text never changes colour over it.
- The Home Battery widget is the gauge and level (plus one line only for time to full, not charging, or a warning), and its popover (`BatteryDetailsView`) has health, cycles, temperature and Low Power Mode.
- One model, `PowerSourceMonitor` (`services.powerMonitor`): every power view reads its committed `state` (`BatteryState`: unavailable, noBattery, onBattery, low, charging, fullyCharged, notCharging, draining). `rawState` puts full (100%, or Is Charged at 95%+) ahead of a top-off trickle; low enters at 20% and holds until 23%. `BatteryStateDebouncer` commits an unplug at once, a plug-in after 2 s unchanged, sub-state changes after 2 s in the first minute on power and then charging → not charging after 10 s, back to charging after 30 s; draining and onBattery ↔ low commit at once. `batteryLevel`, `hasBattery`, `hasReading` and `isOnExternalPower` stay raw IOPS for `AgentPowerAlert` and `LidClosedAwake`.
- Sources, nothing else:

  | Shown | Source |
  |---|---|
  | Level, state, time to full | IOPS (run-loop source, `kIOPSNotifyTimeRemaining`, wake); time to full only while charging, filtered by `TimeToFullFilter` (down at once, up after two higher updates by 10 min or 15%) |
  | Time left on battery | IOPS `kIOPSTimeToEmptyKey`, only on battery or low, filtered by `TimeToEmptyFilter`: nothing for the first 5 min after an unplug, then changed only after two updates in the same direction differing by 15 min or 20% |
  | Maximum capacity, condition | `system_profiler SPPowerDataType -json` (`BatteryHealth`) at start, every 6 h and when the popover opens with a reading over an hour old; a missing key is left out |
  | Cycle count, charger, temperature | AppleSmartBattery (`CycleCount`, `AdapterDetails`) and AppleSmartBatteryPack (`Temperature`), read on each IOPS change, 3 s and 10 s after a plug-in, and the temperature each minute while the popover is open |
  | Live input | `PowerInputSampler` |

  "On battery for …" is the time since the unplug commit. Both times show rounded (`BatteryStatusText.span`: 5 min steps under an hour, 10 min above, "10+ h").
- Power column (`CableManagementCard`), rows in order: the verdict (thumbs up "Keeping up" for charging, fully charged and not charging, with "Charging, with nothing spare" while the input is at the connection's limit; orange thumbs down "Falling behind" for draining; "Not plugged in · On battery for …" unplugged; "On power" on a desktop), Low Power Mode (`LowPowerMode`), Battery health ("87% capacity · 343 cycles", or orange "Service recommended"), then every connected Bluetooth device with a battery in one row. The charger (`ChargerInfo`: AdapterDetails Name, "pd charger" as "USB-C charger"; `connectionWatts` = AdapterDetails Watts; `ratedWatts` from the name), a limit note when the rating exceeds the connection by 10 W or more, and the watts coming in are only in the verdict's help.
- `PowerInputSampler` (nested in the model; only the power column and a drain check retain it): a 1 s `.common` timer reads `SMCPowerSensors` (PDTR watts, VD0R volts). Watts: the 30 s mean, first shown after 3 s of samples, then re-evaluated every 5 s once 10 s exist and changed only by 2 W or 8%. Volts: snapped to the USB-C steps (5, 9, 15, 20, 28, 36, 48 V) within 10%, changed after 10 readings in a row. Release and a gap over 5 s forget the samples but keep the shown values; a plug or unplug and wake clear everything. `isLive` drops after 10 s without a reading. The UI uses it for `atLimit` and the verdict's help.
- `SMCPowerSensors` caches each key's size, type and attributes; integers and `sp78` are little-endian when attribute bit 0x04 is set, `flt` always (`decode`). Failed opens back off 5 s, 30 s, then 5 min; failed key lookups retry after a minute.
- Colour: `PowerPalette.tint` is orange only for low and draining, the theme accent otherwise; "service recommended" is the only other orange text. `BatteryGaugeView` (widgets, popover) and `BatteryPill` (System page) are the only battery glyphs, each with the bolt only while charging.
- Notices beside the notch (`PowerNotice`, `PowerActivityGaugeView`/`PowerActivityLevelView`, the gauge and the level only) come only from commits and the drain detector: plugged in (4 s), unplugged after at least 2 s on power (4 s), low at 20/10/5% (8 s, with a notification) and draining (8 s, with a notification, once per plug-in). A notice of the same kind is merged; a new one replaces it. The drain detector (`DrainDetector`) needs 5 min on power, the level 3 points under its peak and a 60 s input mean of at least 85% of the connection's watts; it clears when the level rises a point or charging holds a minute.
- `LidClosedAwake` runs `pmset -a disablesleep 1/0` (the only way to run lid-closed) through the privileged helper when approved, otherwise osascript with administrator privileges; state is read back from `pmset -g`; it is turned off without a prompt at quit and once per low-battery stretch.
- Power helper (`Helpers/PowerHelper`, target `MacSpacesPowerHelper`, embedded at Contents/MacOS with `dev.opensource.MacSpaces.PowerHelper.plist` in Contents/Library/LaunchDaemons):
  - Registered with `SMAppService.daemon(plistName:)` from the row's "Skip the password" chip, then allowed once in Login Items. The row's context menu has Open Login Items and Remove Helper.
  - Its XPC contract (`PowerHelperProtocol`) is exactly four argument-free calls: `preventSleep`/`allowSleep` (`/usr/bin/pmset -a disablesleep 1/0`) and `enableLowPowerMode`/`disableLowPowerMode` (`-a lowpowermode 1/0`).
  - The helper accepts only `dev.opensource.MacSpaces` from team 28LJG7MXT3 (`setCodeSigningRequirement`), the app checks the helper the same way, and it exits after a minute idle.

### Wisp

- `Sources/Modules/Wisp`. `WispModel.shared` is the assistant: the conversation, the face's mood and the actions. It keeps no data of its own: reminders go through `CalendarService.addReminder(title:due:dueHasTime:)` (a timed one also gets an alarm) and `complete`, notes through `NotesService`, focus through `PomodoroModel`, timers through the first free `TimerService` (showing another slot on the Timers page when needed), and "my day" reads EventKit directly, off-main (`WispDay`).
- Understanding: `WispCommand` and `WispWhen` (pure, `Sources/Core/Wisp`, `Scripts/check-wisp.sh`) parse the everyday requests on every macOS. Anything else goes to `WispBrain` (macOS 26, `#if canImport(FoundationModels)`): Apple's on-device model with six tools that call the same actions; a session lasts 30 minutes so the time in its instructions stays true, and a full context window starts a fresh one. Without the model Wisp says what it can do.
- Voice (`WispVoice`): the mic button listens with on-device recognition only and stops 1.5 s after speech ends (7 s if nothing is said); it won't start while Dictation or the voice teleprompter has the microphone. Answers are spoken (best installed system voice) only when the question was spoken and `wispSpeaks` is on (the toggle in the dock's centre on Wisp's page; turning it off stops a reply being read). Microphone, Speech Recognition, Reminders and Calendar are asked for only by an explicit request (the mic button, a reminder, "my day").
- Where: only its own page (`NotchTab.wisp`, `WispPage`), laid out with no columns. `WispAskField` ("Ask Wisp…") spans the whole page along the bottom. Empty, the eyes (`WispFace` at 80 pt) are the hero in the middle with the greeting under them ("How can I help?" and one line on what works with the current engine), centred together in the space above three quiet suggestions, which sit just above the ask field and fade out once a conversation starts. Talking, the eyes move up into a slim header band at the top centre (58 pt, the face at 68% scale), still emoting, with the model tag at its left (`WispModelTag`: the maker's logo symbol and the model's name, `apple.logo` Apple Intelligence, or Offline) and a quiet Start over at its right. The conversation runs full width below: a short one sits at the bottom, a long one scrolls, newest at the bottom, fading at the top under the header. It's one face throughout, moved and scaled by a single spring between the middle and the header (instant under Reduce Motion), drawn over everything; its big moods may overflow the header without moving the layout. There's no status line: the eyes show it, and it's the face's accessibility value. Both sides of the conversation share one bubble style (13 pt text in the page's foreground, 13 pt corners, at most 72% of the width or 420 pt): yours right-aligned on a slightly stronger fill, Wisp's left-aligned, with what a reply quotes (the item just added or checked off) in the accent (`WispPage.highlighted`). Wisp is on when that page is in the dock (Settings → Apps); there is no other switch and no Settings page. The tag names the model answering plain-language chat from `WispModel.engine` (a `WispEngine`: name, tooltip line, whether a model answers): "Apple Intelligence", or "Offline" with `modelUnavailableReason` as its tooltip; another engine would be another `WispEngine`. The Nook is held open (`isPageEditing`) only while text is typed; collapsing stops listening. Dictation and the voice teleprompter take the microphone from Wisp when they start.
- The face (`WispFace`): two eyes floating on the Nook, with no head, tile or border, white on a dark Nook (glass and Clear included) and black on a light one (`WispFaceStyle`); the theme's accent shows only in the heart eyes. The eyes are the character: each mood is one still pose (`WispPose`, in fractions of the face's size) drawn with plain SwiftUI shapes whose sizes animate (`WispEyeShape`, a rounded rectangle that can slant and shut to a rounded line, never cut into; `WispArcShape`, a thick round-capped arc for happy and closed eyes; `WispMouthShape`; `WispHeart`; `WispStar`), with no Canvas or timeline. Mood changes, the pointer and props are short springs between poses, with a little overshoot, and between them nothing draws. Live, one task sleeps 2.6 to 5.2 s between blinks (sometimes two) and, idle with the pointer away, makes every third one a glance aside; while speaking another opens and closes the mouth every 0.12 to 0.24 s. The page turns the eyes to the pointer in quarter steps at most ten times a second, only when it moves; they slide toward it, the pair leans into it and the far eye gets a little smaller. Within 130 pt they widen, and over them they open wider still; the activity clock lives outside view state, so pointer moves don't redraw the page. A small smile always sits under the eyes, a clean round-capped line that changes with the mood. Moods: idle (two tall rounded eyes and the smile), listening (taller), thinking (squinting, glancing up and aside, a flat mouth), speaking (the mouth opening and closing), happy (thick ^ arcs and a bigger smile), celebrating (stars and an open grin), surprised (very big round eyes and an o), sleepy (after 90 s untouched on the page: closed eyes as gentle cups, a flat mouth, a tilt and z's; pointing wakes it), confused (one eye squinting, a tilt, a flat mouth) and love (hearts, in the accent: thanks). Arcs, hearts and stars don't blink. Props (`WispModel.show`, the transient `prop`): for a few seconds after an action a tiny glyph in the eye colour sits off to the lower right, clear of the eyes and smile, and they glance at it: a mug for a timer named tea, coffee, brew, chai or matcha, a stopwatch for other timers, a bell for a reminder, a page for a note; focus slides shades over the eyes. Clicking pokes it: a startle, then a laugh. Reduce Motion shows each pose with no blinks, glances, chatter, pointer following or transitions. The page's icon in the dock and Settings is `WispGlyph`: the two eyes alone, in the surrounding foreground colour.

## Build, release and updates

- Bundle `dev.opensource.MacSpaces` (keep it stable for settings and update verification); team `28LJG7MXT3`; keychain profile `MacSpaces`. Never commit credentials, generated projects or release artifacts.
- The one package is SwiftTerm (MIT, pinned exactly in `project.yml`; licence in `Sources/Resources/Acknowledgements.txt`). Its build plugin means every `xcodebuild` passes `-skipPackagePluginValidation` (Makefile, CI, package-release.sh).
- `make` builds Release locally. `make release` runs `Scripts/package-release.sh`: universal Release build, Developer ID signing with hardened runtime (the power helper first, with its own identifier), app notarization and stapling, DMG creation, DMG notarization and stapling (two rounds so both pass Gatekeeper offline; `notarytool --timeout 60m`), then signature, architecture and Gatekeeper checks on the mounted app.
- CI (`.github/workflows/ci.yml`, macos-26): all check scripts, plus a Debug arm64 compile check with cached Swift packages, built as the Feature QA harness so the `budget` scope runs on it, report only (a warning, not a failure) until it has passed three times on unchanged main; it runs on every push to main and by hand on other branches; a newer push to main cancels an older run, and a run started by hand is replaced only by another of the same commit. A passing local build is not enough: CI must pass on the exact commit being released. `feature-qa.yml` runs the Debug harness on GitHub's Macs when dispatched (see [CI, Feature QA and preflight](#ci-feature-qa-and-preflight)), uploading the captures; `Scripts/qa-clean.sh` then deletes the branch and its runs, so the Actions history is CI's release runs only.
- **Shipping**: bump `project.yml` and `RELEASE_NOTES.md` (current version only, named in bold), then run `Scripts/ship.sh` in the background with any commit trailer in `SHIP_TRAILER`. In order it:
  1. runs seven checks;
  2. makes a new root commit `MacSpaces X.Y` and pushes it with force-with-lease;
  3. runs `make release` while waiting for CI on the full commit SHA (`gh run list --commit` ignores short SHAs);
  4. tags `vX.Y` and runs `Scripts/publish-release.sh` (Latest; refuses development builds; adds one hidden `macspaces-build` marker);
  5. updates the Homebrew cask, then deletes every older release and tag, first adding each release's download count to `downloads.tsv`.
- **Downloads**: deleting a release deletes its GitHub download count, so `downloads.tsv` (repo root, git-ignored) is the only record of earlier releases' counts; never delete it. Counts before 3.17 were lost. `Scripts/downloads.sh` prints each release's count, the current release's live count and the total. The installer, Homebrew and the in-app updater all download `MacSpaces.dmg`, so the counts are downloads, not people: a release's count is roughly its new installs plus the installs that updated to it.
- `main` is a single root commit, `MacSpaces X.Y`, with no parent; each release replaces it. No recovery bundles, backup branches or spare app copies. A replacement installer for the same version updates that release.
- **Docs-only updates**: `Scripts/publish-docs.sh` replaces the root commit and moves the current tag, installer unchanged. It publishes `README.md`, `AGENTS.md`, `Demos/` and `docs/` only and refuses if anything else differs from the published commit.
- **Versions**: `CFBundleShortVersionString` is the public version (2.x used `major.build`, 2.32 … 2.100; from 3.0 plain names; 1.0.0 predates both). `CFBundleVersion` is an internal integer that must exceed every published build, since updaters compare builds. `check-release-policy` enforces this.
- **Updater** (`UpdateService`, `ReleaseRevision`):
  - 1.14 and 2.38+ read releases/latest; 2.36 and 2.37 read the release list and take the newest non-draft release of their major version (`ReleaseRevision.newest`).
  - Updates download automatically by default, look hourly while running and check GitHub once six hours have passed since the last check, download only over https from GitHub's release hosts (`isTrustedDownload`), and verify the app's version, build, bundle id, signing team (`signingTeam(fromCodesignOutput:)`), minimum macOS and architecture before asking to relaunch. A build this Mac can't run is remembered and skipped.
  - 1.14's updater can't check the minimum macOS, so the current release must keep running on macOS 13.
- **Homebrew**: `zlichtman/tap/macspaces` is the only cask (`depends_on macos: :ventura`; run `brew style --cask` before pushing the tap); `cask_renames.json` moves old `macspaces@beta` installs to it.

### CI, Feature QA and preflight

- **Preflight** (`Scripts/preflight.sh`, before every push or dispatch): one incremental Debug arm64 build of the harness as CI and Feature QA build it (`dev.opensource.MacSpaces.FeatureQA`, then `.WebsiteDemo`, which only relinks), then every `Scripts/check-*.sh`. Output goes to `~/Library/Caches/MacSpaces-preflight/<checkout>-<hash>` (outside iCloud; `--clean` removes it), with the Swift packages shared in `SourcePackages`. It refuses (exit 75) when `mac-status` shows free memory under 40% or swap over 6 GB, or another `xcodebuild` runs, and compiles with `-jobs 4`. A failed build prints its errors, deduplicated, and the checks still run. `--build` skips the checks. While the screen is locked it skips `check-notes`, whose notes file (`completeFileProtectionUnlessOpen`) can't be reopened then. Measured on the owner's 12-core, 18 GB Mac: from nothing 70 s (build 41 s) peaking at 3.0 GB for the whole process tree; after a one-file change 35 s (build 11 s) at 1.2 GB; 0.5 GB on disk per checkout.
- **Step causes**: every `run` step in both workflows runs through `Scripts/ci-step.sh` (`defaults.run.shell`), which keeps GitHub's `bash -eo pipefail` and, when a step fails, writes one line to the run summary and an error annotation, so `gh run view <id>` names it: the check script or `xcodebuild`, then the first compiler error (with a count of the others), else a Swift trap's message (with the lines it printed after a trailing colon, such as each budget overrun), else a timeout, else the last line. `Scripts/ci-step.sh --cause <log>` prints the same line for any log.
- **Feature QA** runs only when dispatched; a push starts nothing, so nothing is cancelled: `gh workflow run feature-qa.yml --ref qa/<name> -f scopes="agent-popout notch-looks" -f clips=readme-hero -f tour=nightBlossom` (`scopes=none` for clips or the tour alone). Every scope runs even when an earlier one fails, each with five minutes at most; the summary has a table of scopes with the result, time and cause (a scope that crashed without a message names its signal, and the first such scope is run once more under lldb, adding the first MacSpaces frame from the backtrace). Clips and the tour run whenever the harness built. Dispatches never cancel one another.
- **What gates a release**: CI on main runs only checks that give the same answer every run (the check scripts and the compile). Timing measurements, such as a performance budget, run in Feature QA as a scope and report there: on GitHub's shared VMs the budget failed on unchanged 3.29 code (passes up to 116 ms against a 33.4 ms limit), and one build measured twice in the same job saw the same pass at 126 ms and then under the limit.
- **Cleaning up**: `Scripts/qa-clean.sh qa/<name>` cancels the branch's running runs, deletes every run whose branch is exactly that one (CI and Feature QA, any outcome), then the remote and local branch (`--keep-branch` keeps it). It accepts only `qa/` names, so main's and the releases' runs are never touched.

### Local promotional captures

`Scripts/capture-demos.sh` builds an isolated WebsiteDemo app and records its clean window with ScreenCaptureKit, using the production Core Animation and Metal effects, real-time timing, no pointer and no audio. Other windows and the desktop are excluded by a single-window filter; the camera housing is a drawn stand-in because physical camera cutouts cannot be recorded. The real app and its preferences remain separate. Screen Recording permission is required for the capture terminal. Leave the desktop unlocked and the demo window visible; the script runs the sequence and closes it automatically. It refuses a locked desktop before building and keeps the display awake only for its own run.

`Demos/music-sequence.json` holds the original five songs, excerpts, order and theme pairings recovered from the existing Music video. `Scripts/demo/prepare-music.py` resolves exact title/artist/album matches and uses the fixed excerpts and playback positions from the original silent video; a missing track, lyric or cover stops capture. Covers remain temporary, outside iCloud, and are deleted with build output on success. Failed runs retain their own build for `--retry --output <folder>`; `--clean --output <folder>` discards that temporary build without deleting exports. Both Feature QA and local capture use this manifest. The reel opens on Home's current Music widget, opens Music and moves through the original five pairings. Separate settled stills and a five-song proof sheet are generated automatically. No interpolation is used.

Run `Scripts/capture-demos.sh --check` for prerequisites, `--music-only` for the reel and five stills, or `--stills-only` for stills without the reel. `--output /absolute/folder` selects a new capture folder; the default is a timestamped temporary folder. The default run also captures supported page stills. It updates local website and README assets through `publish-demos.sh`, with the explicit Music poster taking priority. Nothing is committed, pushed or deployed. Review `music-proof.png`, `site/` and `capture.json`; logs remain in the output folder. Temporary builds, covers and raw movies are removed automatically after successful export. Failed capture folders retain diagnostic output and a retry marker. `--all`, `--music-only` and `--stills-only` can also select the batch on a retry. Each launch uses fresh temporary fixture data and resets only the isolated demo preferences. The panel is pinned while captured. One reusable preview window, at most 560 points wide, sits at the right edge of the current desktop. It uses normal window level, stays on that desktop, does not activate or repeatedly raise the app, and never moves the pointer. The preview can be dragged by its background or covered by other work; the recorder selects only that window. The Debug lyric preview explicitly carries playback state, so native lyric animations run with the song. Export rejects a first-song poster without the expected visible star before copying any assets.
