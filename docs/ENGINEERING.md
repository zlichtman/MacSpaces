# MacSpaces engineering guide

MacSpaces is a native macOS menu-bar app built around the **Nook**: a panel that opens from the physical camera notch, or a synthetic notch on other displays, with a dock of full pages, a Home grid of widgets, a file Tray, compact live activities beside the closed notch and cards under it.

- The version and build live in `project.yml` (and `RELEASE_NOTES.md`). `README.md` is the public page, `Demos/README.md` describes the README images, and this guide is the current state. Agent rules are in `AGENTS.md`.

## Code layout

- `Sources/Core`: pure catalogs and logic: feature catalog and dependency-aware service lifecycle (`Features`), action registry (`Actions`), `CompletedFileTracker` (`Files`), playback capabilities (`Media`), `NoteRepository`. `FeatureCatalog` keeps only shipped features and the fields `NookWidgetKind` reads (title, symbol, summary, permissions, width, compact).
- `Sources/App`: entry, menu-bar menu, `AppServices` (service demand), `ModuleCoordinator` (creates only `NotchManager`), updates.
- `Sources/Modules/Notch`: `Core` (display geometry, per-display windows, hover, collapse/expand, sizing), `UI` (panel shape, dock, live activities, transitions), `Features/Widgets` (Home dashboard and widget views), `Settings` (`NookSettings`, `WidgetOptions`, the General/Notch/Files panes).
- `Sources/Modules/{Actions, Clipboard, Converter, Meetings, Prompter, Voice}`: Find Action, App Intents and Finder Services; the clipboard popup; File Converter and File Tools; meeting controls; Studio (scripts, takes and the teleprompter); dictation.
- `Sources/Modules/Tape`: the window strip: `Engine` (pure model and geometry; `StripLayout` is the layout), `Platform` (Accessibility, hot keys, scroll tap, frame clock, log), `TapeController`, `TapeSettings` and `TabOverlay`.
- `Sources/Services`: media, lyrics, weather, calendar, clipboard, timers, coding stats, updates and other services. `PowerHelperProtocol.swift` is shared with the helper.
- `Sources/DesignSystem`: themes, `Design` motion tokens (open/close/hover springs, `nookDepth` transitions), `OlderMacOS.swift` stand-ins, `RefreshButton` (its arrow turns once per click). All motion honours the system's Reduce Motion (views read `accessibilityReduceMotion`; other code reads `ThemeStore.reduceMotion`, which follows the system setting).
- `Sources/Settings`: the Settings window, search index, Home layout editor and inline sample widget gallery, Clipboard preferences.
- `Sources/Debug`: Debug-only QA harnesses, regression checks and website capture.
- `Helpers/PowerHelper`: the privileged helper. `Tests/`: sources for `Scripts/check-*.sh`.
- `Helpers/VoiceHelper`: `MacSpacesVoiceHelper`, the XPC service for voices from recordings (Siren's engine, in `Engine/`). `Packages/SirenQwen` and `Packages/SirenCosyVoice` are Siren's vendored Qwen3-TTS and CosyVoice 3, with their LICENSE and NOTICE files. `Sources/Core/Studio` (Studio's pure rules for reading and takes), `Sources/Core/Voices` (the model catalogue and store, cross-recording sorting) and `Sources/Services/VoiceHelperProtocol.swift` are compiled into both the app and the helper.
- Shared keys: `WidgetOptions.Keys` (no repeated key strings).

## Compatibility

- Swift 5.9; macOS 13 deployment target; universal (arm64 and x86_64). `project.yml` is the project definition (XcodeGen); the generated Xcode project is ignored. iCloud conflict copies `Sources/Resources/Info *.plist` are ignored by Git and excluded from the project.
- Anything newer than macOS 13 needs `#available` with a fallback. Shared stand-ins live in `OlderMacOS.swift` (`refreshTurn`, `scrollContentTopMargin`, `textFieldKeys`, `NoSearchResultsView`); `onChange` uses the one-value form; EventKit `.fullAccess` is checked with `#available` (`.authorized` before 14).
- Before macOS 14 the Settings search and the Terminal prompt line handle Escape but not ↑/↓, and the refresh arrow uses a plain rotation.
- macOS 14+-only features (listed in README Requirements): Tray Remove Background, Continuity Camera/Desk View in Mirror, ↑/↓ in Settings search and the Terminal prompt line.
- Use explicit captures in nested actor closures (the CI compiler requires it). Locks used from async code are `OSAllocatedUnfairLock`, not `NSLock`.
- Animated views use timer-scheduled (`.periodic`) TimelineViews, not `.animation` schedules, which pause when macOS reports the menu-bar panel as hidden. Avoid `rotation3DEffect` spins (they vanish edge-on and look flat); scale x instead.
- Timers schedule in `.common` run-loop modes so they move while a menu is open.

## Nook shell

- **Geometry**: app pages share a 620×346 base, clamped to the display; Home follows its widgets (legacy manual sizing preferences are kept but don't control geometry). Content starts below the physical camera; a detached dock sits below the panel and the shared hover region includes the gap. AppKit owns window geometry (SwiftUI size propagation is isolated).
  - **The camera**: `NotchGeometry.resolve` turns what a screen reports (`safeAreaInsets.top`, the auxiliary top areas' widths, the menu bar's height) into the closed surface. A notch spans the gap between the auxiliary areas, the inset tall; a screen without an inset gets the synthetic pill (144/156/168 pt by width, 30 tall).
  - **The island** (MacBook Pro with PROLED XDR display, from October 2026): its camera is an oval cutout below the top edge. The built-in display is taken to have it when macOS 27's `NSScreen.touchCapabilities` is non-empty (the only touch Mac display; read through KVC so SDKs without it build and older systems say no). Apple publishes no cutout size or API, so the capsule comes from the best thing known: a measured cutout plus a 1 pt bleed (`Reading.islandCutout`, only Debug captures set it), else the band macOS keeps clear (the auxiliary gap, the inset tall, from the top edge), else a stand-in centred in the menu bar (its height less 6 pt, 3.4× as wide). The closed capsule stays centred on the cutout as it peeks, swells for a file or grows to 26 pt for lanes (`closedTopPadding`), its radius half its height. It opens as on a notch Mac: the panel hangs `cameraGap` below the cutout (`expandedPanelTopPadding`, from `cameraBottom`; pages are `topInset` taller so content keeps its room) and closes back up into the capsule. The island itself is left to macOS 27, which shows its own Dynamic Island there (Spotlight, Siri, Live Activities): while the Nook is open nothing is drawn over it and the whole band down to the panel passes clicks and touches through (`expandedShoulderClearance`). Closed, the capsule's hover area reaches up to the top edge; the agent bubble sits beside the capsule at its height, and the teleprompter hangs below `cameraBottom`. Notched and notchless Macs take none of these paths (`isIsland` false, `topInset` 0).
  - **One model**: `NotchGeometry` is the cutout (`Cutout`: `.notch`, `.island`, `.none`). Nothing is drawn over the camera (the surface over the camera is invisible, `clearHitOpacity` so it still catches the pointer, and turns solid while peeking or taking a file; each activity is a `NotchBubble`, the agent bubble's size, first left of the camera and second right (a song alone is a pair: its cover left in a `squircle` bubble, a continuous-corner square like an album cover, filled by the art; its sound right, bars in a black squircle of the same shape, coloured with the cover's strongest colour (`ArtworkWashStore.tint`, from `CustomTheme.palette`) or the theme's accents; everything else, the agent bubble included, is a black circle with no outline at rest, a timer keeping its countdown as a thin arc in its colour), lanes `AgentPopoutLayout.laneWidth` wide so the agent bubble continues the row). `notchlessHint` shows the resting pill at `notchlessHintOpacity` on screens without a camera. `outline(expanded:surfaceHeight:)` gives the shape: the capsule family, opening into the panel through one animatable path (radii and side inset). The pill is Settings → Appearance → Closed Notch (`notchlessHint`, stored under `notchlessHintKey`); `NotchGeometry.detect` reads it and `NotchManager` rebuilds the windows when it changes.
- **Swipe to change songs** (`NookSettings.swipeToChangeSongs`, Activities → Music, on for new installs): with any song loaded, a sideways swipe with the pointer where the closed notch sits, with the Nook closed or open, or over the open Music page or Home's music widget (`swipesSongs`, `handlePanelSwipe`), is next or previous, once per gesture at 40 pt (`SongSwipe`, following the Mac's scroll direction: next is fingers left with natural scrolling, fingers right without it; ignoring momentum; fingers landing start a new gesture; the other way within 0.3 s of any stroke ending, even one too short to change the song, is the hand returning and is ignored). A swipe waits up to 3 s for a command in flight rather than being dropped, and the `song-swipe` log category records each one. On the notch the cover nudges 5 pt that way on the lane curve; nothing moves under Reduce Motion. The Nook's hover delay doesn't change, so hovering still opens it before a swipe on the notch.
- **Opening**: click always opens; hover, scroll-down and file drags are optional (General → Open & close). File drags open Tray only after pausing near the closed notch. Hover and scroll open only with the pointer on the closed notch itself (`NotchViewModel.isPointerOnClosedNotch`, the notch plus its hover peek); SwiftUI can report hover where the open panel was while it closes, so a hover that starts elsewhere waits for the pointer to reach the notch. Hover and scroll never open the Nook while Mission Control or App Exposé shows (`MissionControl.isActive`), and an open Nook checks about three times a second and closes when Mission Control appears.
- **Performance**: `MissionControl.isActive()` coalesces background WindowServer queries; hover/scroll requests validate their request ID after awaiting. `MotifImages` retains the selected scene, decoded off-main. Decorative motion waits for opening. Closed-lane observations stay in `CollapsedNotchContent`; only settings/lane geometry can resize the host. Statistics, agent scans and Tray metadata run on bounded workers, publishing only current results. `ArtworkWashStore` prepares washes off-main with one reusable Core Image context: the cover shrunk to a 4x4 grid of its colours, saturation 1.6, grown and blurred into soft fields (`ArtworkWashRenderer`), drawn across the whole Music page at 42% (lighter towards the words) when Tint the Music page is on and the theme has no scene or picture; Settings' preview makes the same wash on the spot (`ArtworkWashStore.preview`). The shell's surface tint is a plain gradient under the panel's clip (a gradient-filled animating shape was redrawn by Core Graphics every frame). The microphone/Focus monitor reads CoreAudio and Focus on a utility queue: CoreAudio listeners (default input, its mute and volume) trigger a microphone read when it changes, and a 0.45 s timer reads Focus alone, which has no notification. Covers from every player are decoded once off the main thread and scaled to `NowPlayingInfo.coverPixels` (640), so looks, washes and caches never hold the original art; the cover caches are bounded. LRCLIB decoding, matching and LRC parsing run off-main. The clipboard popup draws clip images from a per-clip thumbnail cache (`ClipThumbnails`). Repeating timers run in `.common` modes (all but the Converter wheel's and the Teleprompter's, which `Scripts/check-timers.sh` lists) and polled values publish only when they change. The scrubber is its own small view on a quarter-second timeline. Live flower scenes run in Core Animation (`FloralLayerScene`: the photo drifts by a layer animation, motes come from emitters), so the app does nothing per frame; other effects draw on a timeline.
- **Hide in apps** (`NookSettings.hiddenInApps`, General): windows are ordered out while one of those apps is frontmost, and the rule is applied when windows are built (`HiddenApps`).
- **Keyboard**: a closed Nook hands the keyboard back (`NotchManager` reorders a key `NotchWindow` on collapse). Widget keys (Delete, ⌘Z, Escape) are ignored while any text input has focus. Keyboard-opened pages stay open until closed.
- **Dock**, three capsules; long lists scroll inside their capsule:
  - App pages (`NookSettings.dockApps`, chosen and reordered in Settings → Dock by the ☰ handle, `DockAppsCard`), Home always last. File drops open Tray even when it isn't in the dock.
  - Controls for the active page: on Home one button per profile (`NookProfile.symbol`, shown only with two or more profiles); on Music the playlist (playlist order), only while Apple Music is the source; other players leave no empty capsule.
  - Settings, with optional Pin and Close beside it (`showDockPin`, `showDockClose`, default and reset on), switched together under Settings → Apps → Dock → Next to Settings.
  - Groups (`NotchTab.groups`): Listen (Music), Talk (Studio, Meetings), Plan (Calendar, Reminders, Clock, Weather), Focus (Notes, Timers), Work (Terminal, Shortcuts, System), Files (Folio) and Extras (Mirror, Wisp); every page is in one. A page turned on goes beside its group (`NookSettings.adding`: after the last of its group before it, else before the first after it, else at the end); a saved dock keeps the order the user gave it.
  - Fresh install and Reset: `NotchTab.defaultDock` (Music, Weather, Calendar, Clock, System, Terminal, Folio, Mirror, Wisp, then Talk: Studio, Meetings). Installs with saved profiles but no saved dock keep `NotchTab.legacyDock`. Meetings/Dictation and Clock were appended once to saved docks (`dock.communicationPagesAdded`, `dock.clockPageAdded`), later removal persists. 3.31–3.34 added Wisp the same way (`dock.wispPageAdded`); a dock that still has it from that loses it once (`dock.wispPageWithdrawn`), nothing else moving, unless `wisp.enabled` was stored true (turned back on by hand). Wisp is on exactly when its page is in the dock: a stored `wisp.enabled` of false (Wisp's old switch) removes the page once, and the key is then deleted so adding the page back sticks; a stored `wisp.dockButton` is ignored. Saved docks drop retired pages on decode; a merged page (`NotchTab.mergedInto`: Dictation into Studio, Clipboard into Folio) is replaced by the page it joined, once, at the first of their positions, the rest keeping its order (`NookSettings.mergingRetiredPages`); Folio already in the dock keeps its own place. Clipboard's migration is written once (`folio.clipboardHistory`: true where the dock had Clipboard, and for a new install; `folio.opensOnClipboard`: true where Clipboard became Folio).
- **Home**:
  - `NookWidgetKind` is the widget catalog; its cases drive the library, persistence and view factory, and new cases need a title, symbol and sizing. Menus list widgets alphabetically (`NookWidgetKind.alphabetical`); Add Widgets groups come from `NookWidgetKind.libraryGroups`, which must list every widget. Saved profiles drop removed widgets and style fields on decode.
  - Fresh Home (profile “Home”): Music (large), Timer, regular Clock (`starterWidgets`, `starterSizes`).
  - Each widget uses one canonical size (`defaultSize`); legacy saved size fields decode but do not control layout. Music is large; Clock, timers, Battery, Keep Awake and Spaces are compact. Adjacent compact widgets stack, oversized profiles scroll, and the empty profile opens the visual gallery. Tiles have no header (VoiceOver names them).
  - Clicking selects (accent outline); Delete/Forward Delete removes; ⌘Z or the Undo bar restores in place for six seconds; Escape deselects.
- **Widgets and pages are one feature at two sizes**: `NookWidgetKind.page` names the page behind a widget (nil for Calculator); the tile's corner button, double-click or "Open …" calls `NotchViewModel.openPage(for:from:)`, which records `pageAnchor` so the page scales out of the tile. Shared pieces live once (`ClipListRow`, `ClipMenu`).
  - Open work: share Calendar/Reminders rows, make each page the feature at page size, then merge `NotchTab` into the feature catalog with a saved-dock migration.
- **Mirror**: one shared camera controller retains one session and serial worker queue across visits and displays. Device discovery/configuration stay off-main and discovery is cached for 30 seconds or until a device change. Opening the Nook can preconfigure an already-authorized camera when Mirror is in the dock; capture starts only with a visible Mirror. Readiness waits for a video frame, interruptions and runtime failures recover or offer retry, and outgoing previews detach synchronously before panel/page transitions. Preview layer updates disable implicit animations. Camera permission remains an explicit button action. The chosen camera (`preferredCameraID`, `mirror.selectedCameraID`) is kept while it's unplugged: Mirror skips disconnected devices, replaces a dead input, falls back to the built-in camera first, looks again 1.2 s after a device change (audio devices don't count, and a running preview keeps running), and returns to the chosen camera when it's back.
- **Service demand** follows enabled widgets and visible pages; a closed page's services keep running four seconds (`lingeringTabs`); safe dock services warm during hover and while open, Music takes a passive system metadata snapshot without AppleScript, page startup reconciles on the next run-loop turn, and stopped work rejects late generations.
- **Closed notch** (live activities): music bars, every running timer in its colour, the meeting countdown, power, paste-queue count, new-screenshot thumbnail, microphone mute, Focus, Keep Awake and a Space change, each toggled on Settings → Activities → Beside the notch.
  - Keep Awake (`CollapsedActivityKind.keepAwake`, after the song in priority; `showKeepAwakeLiveActivity`, on for new installs and off for installs that already had a stored dock): a bubble with the widget's cup in the accent, with a thin accent arc of the time left (`KeepAwakeService.expiresAt`, `duration`) when it has a limit. The countdown is a `TimelineView` on `KeepAwakeCountdown`, which yields a date only when the label changes: each second under an hour ("42:07"), each minute over it ("1h 05m"), none after the end. Feature QA `notch-looks` captures it alone, without a limit and beside a timer (`looks/<cutout>-<look>-awake*.png`).
  - Space change (`CollapsedActivityKind.spaces`, `showSpacesLiveActivity`, off by default; Settings → Activities → System controls → Desktop changes): for `SpacesMonitor.activityDuration` (2 s) after the change settles, a bubble with the desktop's number. It comes after the song in priority, so it never displaces a song, a timer or a notice: it shows in a free slot, or for a moment in Keep Awake's. Beside a song alone it takes the slot outside the cover.
  - Arriving and leaving: an activity slides out from under the camera and leaving slides back under it, the reverse, on one curve (`Design.laneAnimation`, 0.34 s; leaving is the arrival's curve mirrored), never fading or shrinking. Each side is a `TuckedActivity`, moved by its own state rather than a SwiftUI transition (a view being removed keeps its old place, so a transition only faded it where it sat); an activity being replaced tucks away before the next comes out, and one that stays changes in place. Bubbles sit in fixed slots placed on the camera (outside the surface, which shifts and resizes; the slot outside a song's cover is always there, empty until it's needed), each sliding its slot's width. `CameraEdgeMask` hides what crosses a slot's camera-side edge, so it tucks under the hardware, an island's capsule or a notchless pill alike. `CollapsedNotchContent` sets `NotchViewModel.shownActivities` on the same curve, so the shell's surface and offset follow without observing the services. Reduce Motion: a plain fade. Feature QA `bubble-exit` captures it frame by frame.
  - Opening and closing beside them: the open surface drops from the closed surface and then widens (`Design.openDownAnimation`, `openOutAnimation`), and closing draws in and then rises (`closeInAnimation`, `closeUpAnimation`), so it never sweeps sideways over the bubbles. It draws only on the camera's outline (`NotchContainerView.drawsOnCamera`): closed, the room beside it only catches the pointer (an invisible fill at `clearHitOpacity`) and the hover peek grows down alone while bubbles are out; opening, the bubbles tuck under the camera (`Design.bubbleTuckAnimation`, 0.16 s, `TuckedActivity.held`) as the panel drops from the camera's outline beside them, and it widens once they've gone (`openOutAnimation(afterBubbles:)`), so nothing filled shows where they were until the widening passes there; closing is the reverse: in and up to the camera's outline, solid until it's there (`Design.closeSettle`), then the bubbles slide out (`bubblesOut`). A file swelling the notch grows from the whole row. Reduce Motion: both directions together, the bubbles fading. Feature QA `open-morph` captures it frame by frame, and `open-morph-song` the song alone after a hover peek, before and after (`open-morph/song/`).
  - Each side is as wide as its bubbles (`collapsedLaneWidth`, `AgentPopoutLayout.laneWidth`; the timers' row by `timerLaneWidth`). Power feedback precedes routine system-control feedback.
- **Agent pop-out** (`AgentPopout`, pure placement and visibility in `AgentPopoutLayout`, state in `AgentFace`): a round bubble `AgentPopoutLayout.gap` shorter than the closed notch (`bubbleSide`), sitting that gap below the top edge and level with the notch's bottom, slides out `AgentPopoutLayout.gap` (2 pt, the clear look's bubbles too) right of the closed notch and its lanes (`NotchViewModel.closedNotchFrame`, via `NotchManager.agentAnchor()`), on the notched display, showing the agent's own app icon (`AgentActivityMonitor.agentIcon`: Claude's app for Claude Code, the Codex app, which ships as ChatGPT, for Codex; else the app the session runs in; else Terminal's; never a stand-in symbol, the tick for a finished session sitting on that session's icon). While a coding agent needs you its accent ring breathes (`AgentPopoutLayout.pulse`, 1.6 s), with a count for two or more. With Settings → Activities → Show the bubble while agents work (`agentActivity.peekWhileWorking`, off unless chosen, as before the setting existed) it also shows while a session works (the newest working session's icon, the ring fainter and slower) and shows a green tick for `AgentFace.cheerDuration` (4 s) when one goes from working or waiting to done (`AgentPopout` compares each scan's states). Waiting beats a tick, which beats working (`AgentFace.mood`). The ring breathes as one repeating Core Animation group on its layer (`AgentPulseRing`, per mood), so the app does nothing per frame; Reduce Motion holds the ring still. It's a non-activating `.statusBar` panel with `sharingType = .none`; it hides while the Mac is locked, a Hide in app is in front or that Nook is open, and moves when the notch's lanes change (`NotchManager` calls `refresh()`), sliding with the row on its curve (`Design.laneTimingFunction`; under Reduce Motion it fades out and back in). Clicking opens the Terminal page's Agents tab with the waiting session (else the newest working one) outlined, not pinned, so it closes when the pointer leaves (`NotchManager.openAgents(session:)`, `AgentActivityMonitor.spotlight`); its menu also goes to the agent's app. The notch's hover check skips the bubble. Nothing drops down under the notch: notification cards and the reader of Notification Center's store were removed.
- **Menu-bar menu**: while an update waits (`UpdateService.status` is `.available`), Update to MacSpaces X first (it downloads and installs), and the icon (`MenuBarIcon`) carries a dot; then Open Nook, Find Action (with its hot key), Enable Nook, File Converter ▸ (Convert by Shift-Dragging, Open File Tools), File Baskets │ Settings │ Check for Updates │ Quit MacSpaces. No ellipses.
- **Find Action** (`ActionSearchWindow`, default ⌃⌥Space, set in General → Keyboard) searches MacSpaces actions and Apple Shortcuts, not apps or files. Optional direct page shortcuts (⌃⌥N Home, T Tray, M Music, K Terminal, D Studio's Dictate).
- **App Intents** (`MacSpacesIntents.swift`): open a Nook page, stage files in the Tray, convert files and return the results. **Finder Services** (`project.yml` NSServices): Add to MacSpaces Tray, MacSpaces File Tools.

## Settings

- Every page follows one order: what it is and its main switch, everyday options, rare options, then permissions and data. Drawers (`SettingsDrawerCard`, and `SettingsDisclosure` for a part inside a card) hold only long lists or rare parts and start closed; short cards are always open; one card per idea. Two or three choices are a `SettingsSegmentedPicker`, more a pop-up menu, on or off a toggle. Captions are one line (`SettingsCaption`, the rest in its tooltip). A card's parts sit under `SettingsSection` headings, each a search target. A card with a preview uses `SettingsPreview` (the Nook's colour, 200 pt high, 12-pt corners), and every setting in that card changes it.
- Pages, in order (`SettingsDestination`), under three non-collapsing sidebar labels (`SettingsDestination.section`); there is no About page:
  - **Core** section:
    - **General**: updates with the version first (a waiting update is the first thing it shows), then startup, displays, open & close, keyboard, hide in apps, and reset.
    - **Appearance**: only the theme list (`TerminalThemeList` in a plain panel, no header, drawer or subtitle; search lands on it as "Themes"), starting with its search bar. The page fills the window (`SettingsPage(fillsHeight:)`, which passes the window's height down as `settingsViewport`): the list grows so the panel ends one page margin (28 pt) above the window's bottom with the colours bar at its foot, measured from where the list starts and how tall the bar is, never shorter than its matches need (up to 404 pt, so a small window scrolls), and it resizes with the window; the header keeps its place. Arrow keys flip through its themes, applying each (`ThemeArrowKeyRouter`, `GridMove`), unless a text field has the keys; up or down in the Terminal list's search box moves focus to its results, keeping the search. The router sends the keys to whichever theme list is in the window, Appearance's or the Agent card's (`setAgent`, registered with the list's view), never both. It also holds Closed Notch (`ClosedNotchCard`: the pill on displays without a camera and a Circle or Squircle shape per `NotchPopOut`, `notch.popOutShapes`, where unset is the default, the song a squircle and the rest circles; the agent bubble stays round). It is a `SettingsDrawerCard`: Closed Notch stays closed until the header is clicked or a search lands on them, remembered in `WidgetOptions.Keys`.
    - **Permissions** (`WidgetAccessSettings`): each permission's live status, re-read every 2 s while open; opening it requests nothing, and a row's Allow or Open Settings button asks or opens System Settings.
  - **Notch** section:
    - **Home** (case `widgets`, `NookSettingsPane`): compact profiles, visual layout with inline removal and drag reordering, and an inline widget gallery. Gallery previews use sample content and start no services; the starter previews share the real Music, Clock and Timer components, and each gallery row fills its width. Typed `dev.opensource.MacSpaces.widget` drops add into the layout or native Nook; a drag temporarily pins Home, restored on finish/cancel. Selecting a layout preview gives it keyboard focus: Delete/Forward Delete removes it and Escape deselects; keys in text fields keep editing text.
    - **Dock** (case `dock`): the Dock card (`DockAppsCard`): the dock's pages as short rows (symbol, name, its group, the switch and the ☰ handle to reorder), then Add pages, the other pages as chips under their group names (Listen, Talk, Plan, Focus, Work, Files, Extras), a click adding the page beside its group; then Next to Settings. Page-specific controls stay on their pages.
    - **Activities** (case `activities`, `ActivitiesSettingsPane`): Beside the notch, then Closed Notch (a drawer).
  - **Tools** section, only the apps inside MacSpaces, each a page of its own:
    - **Heartable** (case `heartable`, `HeartableSettingsPane`): Music Player (`MusicPlayerCard`), Swipe, Local files (`LocalFilesCard`: Show covers and lyrics from your local music files, off by default, with the chosen folder), then Spotify. Music Player opens with one live preview, the real Music page (`MediaPlayerView`) at 60% with the playing song, or a still sample when nothing plays, over the cover's tint when that's on; then Look (Standard, Vinyl or Shelf, segmented), Album art (the ASCII switch, locked on under Vinyl, then Style, Scene and Around menus and Detail and Colours segmented, dimmed while the cover isn't ASCII), the cover-tint switch and, under Vinyl, Vinyl's colour map folded under Customise.
    - **Tape** (case `tape`, `TapeSettingsPane`): while off, a card with the logo, the switch, the status and the Accessibility note, and Desktops for naming them; while on, Desktops also has a Tape switch per desktop (hidden without the private list), then Displays (with more than one), Layout, Trackpad, Managed Apps, Managed Windows (a drawer, `settings.drawer.tapeWindows`), Keyboard and Mac Setup and log. The sidebar and search results draw `TapeMark` instead of a symbol, and `SettingsCard` takes a `mark:` for its header.
    - **Tsukumo** (case `tsukumo`, `TsukumoSettingsPane`): Agent (`AgentSettingsCard`: Wisp or KemoSabe on Wisp's page, `WispCharacter`, `wisp.character`, picked from live previews on the Nook's colour, `AgentChoice`; then Colours, one palette for both, `agent.palette`, from the theme list with Standard last in Editorial, and Custom from the colour wells (Face, and Body for KemoSabe, `agent.customFace`, `agent.customBody`), with a Glass level, `agent.glassLevel`; see Agent colours), the chat card named for that agent (`WispSettingsCard`, found by search as Wisp either way, `SettingsCard(anchor:)`, `SettingsSearch.title(of:)`): one line on the barrier, then Connected, a row each for Claude and Codex (`WispConnectionRow`: its mark, Signed in, Not signed in, Not installed or Key saved, Connect with the command-line tool or API key, `wisp.<provider>.via`, a key field for the key, and a Model menu, `wisp.<provider>.cliModel` or `wisp.<provider>.model`), Another service once added (address, model and key), then the gateway's Rules (`GatewayRulesSection`: the owner's own words like a system prompt, `gateway.rules`, one per line, and Ask me before sharing, `gateway.askFirst`, off unless chosen); who you talk to is picked in the chat. Then Coding agents (the agent pop-out and its hooks), then Voice (`VoiceSettings`: Open Studio, which opens the Nook on Studio's Voices, and the voice models' downloads; see Voices from recordings. The voice replies are read in, `wisp.voice`, Automatic unless chosen, is chosen in Studio's Voices from Automatic, approved voices from recordings and `WispVoices.choices()`: Personal Voices, then only the two best Premium or Enhanced voices for your language (a man's and a woman's where both exist; the compact standard voices sound poor and aren't offered), plus any voice already saved for the agent or Studio; Use My Personal Voice asks for Personal Voice on macOS 14+ only from that row); the models sit folded under Voice models, open while one downloads. Colours and Voice models are `SettingsDisclosure`s on their saved keys (`settings.drawer.agentColours`, `settings.drawer.recordedVoices`), and Connect with is segmented. ## Features by area

### Music and lyrics
- Lyrics show only on the Music page and advance only while it's visible; lookups may start while the Nook opens (`TeleprompterService.prefetch`, from `AppServices.prewarmDockPages` with Music in the dock and the player already being read). The Media widget mirrors the page (slim scrubber, no artwork wash) without lyrics.
- Lyrics follow the look: the Standard look sets Poster in its lyric area (`StyledLyricView`); the Terminal look (`TerminalMusicView`) sets its own line under the title (`TerminalLyricLine`). Both use the theme's accent and ink. There is no style setting.
  - Every line change, a repeated line included, has its own `TeleprompterService.lineID`; styles key their entrance on it. The shared handover is a 0.18 s fade.
  - Poster sets the longest word (filler such as "something" excepted) as a condensed headline; supporting text keeps a readable floor (11–13 pt). Each line keeps its own composition (`PosterLyric.composition(for:)`): mostly left-aligned, flush right only for short lines. Short tails sit beside the headline at its natural width; longer phrases stack below. Words before the headline are always in the italic serif voice at near-full ink (never a pale tracked caption).
  - Terminal (`TerminalLyricLine`, shared by both looks) is the current line in Menlo 15 pt, in the accent, up to two lines, fading over on each line change.
- Lookup (`TeleprompterService`, pure logic in `Sources/Core/Media/Lyrics.swift`): LRCLIB's exact `/api/get` (title, artist, album, length), then searches by title and artist, free text and title alone. Matches must agree on title and artist (edition suffixes and features ignored, across scripts via `latin`/`similar`); timed lyrics from another cut lose to the right length. A song Spotify plays from a file (`NowPlayingInfo.localTrack`, from the script's `spotify:local:` ID; a MediaRemote reading keeps the one the script gave for the same song) is often another cut than the release LRCLIB timed (leaks, demos, other intros): its lookup is strict (`Lyrics.best(…, strictTiming:)` → `fittingFile`), so a record keeps its timing only when its length is within `localTimingTolerance` (2.5 s) of the file's (Spotify's duration, else the ID's seconds) and no line starts after the file ends; any other record, one of unknown length included, keeps only its words (its plain lyrics, else the LRC's text) and shows untimed. Before that, with the local-files switch on, the file's own lyrics come first (`LocalCovers.lyrics(for:)`: an ID3 `SYLT` frame's timed lines, `Lyrics.parseSYLT`, millisecond stamps only, with a karaoke frame's syllables joined into lines at its newline marks; else an MP4 `©lyr` or ID3 `USLT` text, timed when most of its lines start with an LRC timestamp, `Lyrics.embeddedLines`, LRC header tags dropped and stray stamps stripped from plain text); timed lines that run more than a second past the file's end were timed to another cut and show untimed. They're read fresh for each song and never cached. A file's LRCLIB lookup goes on past a record that only gave words (its timing fit nothing yet), in case a later search holds an upload as long as the file. Records with missing/null duration are accepted and malformed ones skipped individually. A busy or failing LRCLIB (503, 429, timeout) is asked again 1.5, 3, 6, 12 and 24 s later, then every 30 s (14 tries, about 5 minutes, while the song plays), showing the busy message after the fifth; lyrics.ovh's plain text stands in only after two tries, and is the answer only when LRCLIB has no match. Intros and blank LRC lines clear the lyric; `[offset:]` applies (milliseconds, positive sooner). `Lyrics.lrcStamp` reads "[mm:ss.xx]" and the variants taggers write ("[mm:ss:xx]", "[mm:ss,xx]", milliseconds, no fraction); enhanced LRC's word stamps are dropped; section labels ("[Chorus]") are dropped from plain lyrics.
- No-lyrics layout (`TeleprompterService.showsNoLyrics`, rule in `NoLyricsLayout`): the Music page centres a larger title when the song has no lyrics. A cached answer, "none" included, shows at once, before the file is read or LRCLIB asked (a stale one is checked again afterwards). A definite "none" (LRCLIB no match and lyrics.ovh nothing, instrumental, no title or artist, no captions) centres it at once. While the lookup runs, a song change keeps the previous layout for `grace` (0.6 s, longer than a cache hit, the file's own lyrics or LRCLIB's exact match usually take, shorter than a wait anyone reads as stuck), so songs without lyrics in a row stay centred and songs with lyrics never dip; after that the lyric layout shows while it looks. No answer by `deadline` (5 s: LRCLIB busy and retrying, lyrics.ovh slow, offline) centres it anyway; the lookup carries on and lyrics that arrive later lift the title back. Captions from the player itself count as lyrics. Blanked words are restored from lyrics.ovh (`uncensor`).
- `LyricsCache` (Caches/…/lyrics.json, 500 songs, written off-main): timed lyrics stay, plain lyrics are looked up again after a week and "none found" after a day; failures are never stored, except that LRCLIB's no match is kept when lyrics.ovh couldn't be reached, checked again after `partialRecheck` (6 h, the entry's `recheck`), so a replay shows the no-lyrics layout at once. Songs are keyed by title, artist and album (`track|…`), local files by their ID (`local|Artist|Album|Title|Seconds`), so a file replaced by another cut is looked up again.
- Timing nudge (`LyricNudge`): the Music page's right-click menu offers, for timed lyrics, Show Lyrics Sooner and Show Lyrics Later (0.5 s steps, at most 30 s either way) and Reset Lyric Timing once moved (`TeleprompterService.nudgeTiming(by:)`). The nudge is saved per song key in `media.lyricNudges` (unset: none; the newest 300 songs kept) and shifts the song time the lyrics use (`lyricOffset`: line changes), never the player or the scrubber; captions and untimed lyrics offer no nudge.
- Page menu (`MusicPageMenu`, `RightClickCatcher`): right-clicking or Control-clicking anywhere on the Music page opens the Nook's own themed menu (`nookPopover` with `NookMenuRow`s) at the pointer: Look (Standard, Vinyl, Shelf, the same setting as Settings → Heartable → Look, `music.look`) and, for timed lyrics, the timing nudge. The catcher takes only those clicks; every other click reaches the page.
- One clock: `NowPlayingController.estimatedElapsed` drives lyrics and the scrubber. A reading that agrees with the estimate within 0.3 s changes nothing (`NowPlayingClock.agrees`), so the clock never jitters and observers redraw only on real changes. MediaRemote's elapsed time is as of its timestamp; AppleScript readings are timed inside the runner. `LyricTimeline` sets one timer for the next change: sung lines show `LyricTimeline.lead` (0.25 s) early, rests and caption ends exactly on time. Dragging the scrubber moves the lyrics with it (`TeleprompterService.scrub(to:)`); after release they hold the target until the player reports the seek (at most 2 s).
- Reading the player: polling scripts are compiled once (`AppleScriptRunner.runSynchronously(_:reuse:)`). `NowPlayingClock.pollInterval`: 1 s while a position view shows and a song plays, 2.5 s playing otherwise, 4 s paused, 0.3 s for the first 3 s of a song without a cover. Spotify's and Music's change notifications refresh at once. MediaRemote, which answers nothing to apps outside Apple's list on macOS 15.4+, is skipped for 30 s after a script found a track it missed.
- Covers: `SpotifyCovers` listens for Spotify's PlaybackStateChanged notification, refreshes at once and fetches the oEmbed cover (300 px, then 640 px). If no cover arrives, `ArtworkLookup` waits 1.2 s and searches iTunes then Deezer once per track, accepting only a normalised artist + album/title match (cached; misses remembered; real app only). `HeldArtwork` keeps the previous cover (and the wash) up to 1.5 s while the next loads, then fades the new one in over it (the old one stays drawn, so nothing dims). A cover that is the same picture (`CoverLook`, an averaged 8×8 thumbnail: Spotify's 640 px copy after its 300 px one, the next song on the same album) swaps in place with no fade and keeps its wash.
- Local files (`LocalCovers`, pure parsing and matching in `Sources/Core/Media/SpotifyLocalFiles.swift`): Spotify shares no cover for a song it plays from a file on this Mac. Its ID is `spotify:local:Artist:Album:Title:Seconds` (fields URL-encoded, "+" for spaces; `SpotifyLocalTrack`), its AppleScript `artwork url` is empty, oEmbed knows nothing of it and MediaRemote answers MacSpaces nothing on macOS 15.4+ (probed on macOS 27: an empty dictionary). Off unless Settings → Appearance → Music Player → Local files → Show covers and lyrics from your local music files is on (`media.localFileCovers`, default off). The files usually sit in folders macOS protects (iCloud Drive, Documents, Desktop, Downloads, other volumes), so turning the switch on opens an `NSOpenPanel` ("Choose the folder with your music", folders only, starting in the first folder `watch-sources.bnk` names, unchecked so nothing inside it is opened, else ~/Music; `LocalCovers.chooseFolder`, a sheet through `SettingsWindowController.runPanel`). Choosing there is the user's grant, so macOS asks nothing; the folder is kept as a security-scoped bookmark (`media.localMusicFolder`), opened on the worker with `startAccessingSecurityScopedResource` while the bookmark stays the same (a stale one is saved again), and cancelling leaves the switch off. The folder's name (read from the bookmark, nothing opened) shows under the switch with Change and Remove; Remove forgets it and turns the switch off. With a folder chosen, only index entries inside it (by its path and its symlink-resolved path) and only files found under it are read; Spotify's `.bnk` files in Application Support need no permission. With the switch on and no folder (turned on before folders were asked for), the folders Spotify names are read as they always were, including listing them as the switch turns on (`switchedOn`), and the row offers Choose Folder. Spotify's script also returns `spotify url of current track`, and its PlaybackStateChanged notification carries the same ID as "Track ID"; either starts a lookup. The file comes from Spotify's own index, `~/Library/Application Support/Spotify/Users/*-user/local-files.bnk` ("SPCO", then per file title, artist and album as 0x09 strings, seconds as a 0x10 varint, a few fields and the absolute path; read again only when it changes, files over 8 MB skipped), matched on title and artist, album when both name one, and length within 2 s; several fitting files give none. A song not yet in the index is looked for by name (the title, maybe after a track number or the artist) in the chosen folder, else the folders `watch-sources.bnk` lists (a gzip member; at most 20,000 files, five levels deep, listed for ten minutes), a file in the artist's or album's folder first, and used only if its length agrees. The cover is the file's embedded picture (`commonIdentifierArtwork`, else iTunes `covr` or ID3 `APIC`, through `AVURLAsset`; at most 16 MB, 8 s; a file iCloud hasn't downloaded, dataless by `SF_DATALESS` or `ubiquitousItemDownloadingStatus` `.notDownloaded`, is never read but asked to download, and the two-minute retry finds it), scaled to 640 px on one utility worker; a newer request drops an older result. Covers are cached by the local ID (32 kept); a miss is tried again after two minutes, and no match keeps the placeholder. The same switch, file match and worker read the file's own lyrics for the lookup above (`lyrics(for:completion:)`, `AVURLAsset` metadata, 8 s, text over 256 KB ignored). Nothing is sent anywhere; only the real app's bundle identifier reads files.
- With nothing playing the Music page shows one centred invitation with a button per installed player (Spotify, Music) that opens it.
- Song details go through `TrackMetadata` (pure, in `TrackTitle.swift`), for display only (lyrics lookups, their cache keys and artwork matching use the player's own strings): song name, main artist, featured artists, the album without edition details (`TrackTitle.album`, which also drops "(Original Soundtrack)"-style suffixes; hidden when it repeats the song or artist) and versions as short tags ("Live", "Remastered 2011"). `ArtistCredit` splits the artist field: "A feat./ft./featuring B" and "A (feat./ft./with B)" give A and B; the main credit is shown as written and never split ("Simon & Garfunkel", "Earth, Wind & Fire"), and a bare "with" stays in it. Titles add "(feat./ft./featuring/with B)" and an unbracketed "Song feat. B" (not "ft." or "with", which real titles use); a credit already named is dropped. A name with a spaced dash is one artist, stage name first ("Lucy - Cooper B. Handy"), and its tag keeps the stage name. The player sends Boy Harsher's "Autonomy" as title "Autonomy (Ft. Lucy - Cooper B. Handy)", artist "Boy Harsher", album "The Runner (Original Soundtrack)", which shows as "Autonomy" with a FEAT. LUCY tag over "Boy Harsher · The Runner". The Music page shows the song with small outlined capsules beside it, featured artists first ("FEAT. LUCY"), then versions; under it the artist line (`ArtistAlbumLine`): the artist is never cut, and the album truncates into the space left and drops when under 44 pt remain. The widget shows the song and the same artist line, without the capsules; hovering either shows the player's full strings. Once a lookup finds no lyrics (`TeleprompterService.hasLyrics`), the title and artist centre larger in the column; the lyric view stays mounted to keep the lookup alive. Transport buttons show a hover highlight (`hoverHighlight`).
- Devices (`AudioOutputs`, `MusicDevicesView`): the fourth view in the dock's Music group lists CoreAudio's outputs with a tick on the current one; a click sets the default and system output. It reads on a utility queue, listens only while the view shows, and never scans, connects or asks for a permission.
- Apple Music's dock control shows playlist order, not private Up Next. Spotify's local integration exposes no queue; other players have no Music dock controls.

The Nook stays open while the bar holds unsent text.

The selection is one highlight behind the rail, placed from the tile metrics (`TerminalPage.top(of:)`) and sliding between tiles (no slide with Reduce Motion), its accent bar inside it. A tile's name shows after a 450 ms hover in a capsule to the right of the rail, over the tab and clear of every tile; VoiceOver reads the names.

The line is a list of texts, longest first, shown through `ViewThatFits`, so it's shortened rather than cut mid-word. Every button on the page is `TerminalButtonStyle` (22 pt, the accent for the main action, dimmed while disabled), cards are `TerminalCard` (uppercase caption, 12 pt corners) and lists use `TerminalRow` (36 pt, 10 pt sides, 9 pt corners, 4 pt apart: name with a short label, a secondary line, trailing values or buttons, and a leading image only when it means something, the agent's app icon). Each tab fills that space: cards in a row share its height (`section(_:fill:)`) and charts (By day, Months) scale their bars to the height they get. Today is two columns: today's totals large in their Tokens card (what each agent wrote under them, Claude's five-hour window at the foot) beside Codex limits and Most used; GitHub is the Last 53 weeks calendar card above the stat tiles and Months, one height.

Self-updating casks (`auto_updates`) are judged by the app on disk, because Homebrew's record stays at the version it last installed while the app updates itself: on the same task `HomebrewCatalog.reconciled` reads the app's `CFBundleShortVersionString` (its app artifact's target, else /Applications/<name>.app), shows that as installed, and keeps the cask outdated only if that app is older than the cask's version (`isOlder`: dotted numbers, a `,build` part ignored) and Homebrew also calls it outdated (otherwise its upgrade would do nothing); an app that can't be found or compared keeps Homebrew's record. Upgrade and Uninstall run only from their buttons; Update also runs on its own when the tab opens and the lists are over an hour old (`HomebrewStore.checkIfStale`, `HomebrewCatalog.needsAutomaticCheck`, tried at most hourly), with no strip and silently if it fails, the header saying it's checking. - Agents (`AgentActivityMonitor`, Settings → Activities → Coding agents that need you, off by default; one that needs you shows the agent pop-out beside the notch):

Claude Code gets UserPromptSubmit, PreToolUse, PostToolUse, PermissionRequest, Notification, Stop and SessionEnd; Codex the same without Notification, which it doesn't have. Every event of ours is removed before installing, so dropped events go; enabled installs are upgraded on launch.
  - It writes per-session status plus the first KB of the prompt (skipping injected text that starts with `<`), tool and notification payloads, the host app, the pending permission request (`.ask`: the hook's process id, then the payload) and, at Stop, `last_assistant_message` (`.reply`). `AgentHookConfig.describe` turns a call into "Editing X" (MCP tools by their own name), `request` into a title and the exact command, `userPrompt` drops injected prompts and `appLabel` hides an app that repeats the agent's name. Finished sessions stay listed for 30 minutes.
  - Answering (Settings toggle, on by default; `agentActivity.answers`): while MacSpaces runs it touches `agent-activity/alive` every 5 s. A PermissionRequest hook that finds it fresh waits up to `answerWait` (45 s; the hook's timeout is 60 s) for `<session>.answer` = "<its pid> allow|deny|app" (`AgentActivityMonitor.answer`), checking MacSpaces is still alive every 5 s. Allow or deny prints the `hookSpecificOutput.decision` both agents accept (deny with "Denied in MacSpaces."); `app`, a timeout or no MacSpaces prints nothing, so the agent's own prompt decides. Each answer covers one request; nothing adds permission rules. Claude's AskUserQuestion can't be answered by a hook, so it's shown with a way to the app.
  - The Agents tab lists sessions that need you first (cards with the request, its command, Allow, Deny, Answer in App and a countdown), then working, then finished ones with their last reply; the bubble's menu has Allow and Deny for the longest-waiting request.
  - Codex runs a hook only once it's reviewed in Codex's `/hooks` (and again after it changes). `CodexHookReview` asks Codex's app server (`codex app-server`, `hooks/list`, read-only; Homebrew, npm or ChatGPT's bundled binary) how many of ours aren't trusted, at most once a minute while Agents or Settings shows and after MacSpaces rewrites the Codex hooks; `CodexHookNotice` explains the fix.
- Dev Servers widget (`DevServers`): lsof LISTEN sockets of the user's own processes (no macOS services or app bundles except Xcode's developer tools), cwd via proc_pidinfo, Stop with SIGTERM after checking process-start identity. On the Terminal page's Servers tab it has the page's header and rows, and its empty state is the page's.

### Clipboard
- History is memory-only unless Keep history after quitting is on; it excludes concealed/transient types and text shaped like a credential (`ClipboardSecrets`: private keys, prefixed tokens, JWTs, Luhn card numbers, `.env` blocks).
- Kept history, `clipboard-pins.json` and `scripts.json` are sealed by `SecureStorage` (AES-GCM, "MSE1" header; key via HKDF from a Secure Enclave P-256 agreement, or a keychain key without an enclave; `storage-key.json` 0600). Older plaintext files are read and re-sealed.
- Popup (`ClipboardPopup`, Carbon hot key `ClipboardPreferences.shortcut`, default ⇧⌘C, no permission): a non-activating key panel at the pointer, centre or under the notch with Maccy-style keys (↩ copy, ⌥↩ paste, ⌥⇧↩ plain text, ⌘/⌥1–9, ⌥P pin, ⌥⌫ delete, ⌥⌘⌫ clear). Pasting reactivates the previous app and posts ⌘V (Accessibility, asked on first use; otherwise clips are only copied). The shortcut keeps the clipboard service running.
- There's no Clipboard page: the history is Folio's Clipboard place. With Folio in the dock and `NookSettings.folioClipboardHistory` on, the service runs so history is there when Folio opens; Folio opens on Clipboard with `folioOpensOnClipboard`, and the Home Clipboard widget's expand button and the Clipboard App Intent open it there (`NotchViewModel.pendingFolioPlace`, read by `folioStartPlace` and cleared when Folio closes). `NotchTab.clipboard` stays only as a raw value that resolves to Folio.
- `ClipboardPreferences` (Settings → Folio → Clipboard): history size (default 200, up to 1,000), sort, search mode (exact, fuzzy, regex, mixed), pins position, preview, pause/ignore-next, clear options, auto-delete, and `ClipboardFilter` (kinds, apps, regex, pasteboard types).
- Entries carry `firstDate`, `copyCount` and `recognizedText` (Vision OCR on image clips, off the main thread); `ClipboardQuery` parses `@kind`, `@app`, `#collection`. Snippets, collections, pin keys ⌃A… (no N, P, U), drag out, colour picking, `ClipMenu` shared by popup, page and widget. `MaccyImport` reads Maccy's Storage.sqlite read-only, applying credential, app and private-type filters.
- Paste queue (off by default): each ⌘V or ⌥⇧⌘V puts the next clip on the clipboard 0.2 s later, in order or newest first. Seeing ⌘V elsewhere needs Accessibility, requested only when turned on. While it's on, Folio's Clipboard place shows its card above the clips (`PasteQueueCard`, drawn by `FolioClipGrid`): what ⌘V pastes next, the order, Clear and, while Accessibility is missing, Open Settings. The closed notch shows only a count; turning it off puts the last copy back.
- Pin letters (⌃A…, no N/P/U) are stored on each pin (`pinKey`) and kept while it stays pinned; new pins take the first free letter, and Maccy imports keep Maccy's letter when it's free. The popup follows `monitor.entries` while open (right-click actions, new copies and OCR show at once; the selection is kept by id). ⌥↩ pastes into the app that was in front when the popup opened, and only copies if that was MacSpaces. ⌘V is sent with the key that types "v" in the current layout.
- Maccy import (Settings → Folio → Clipboard, after Recording) reads and filters off the main thread, merges by date (newer clips here are never pushed out; existing dates aren't made older), reports what was kept after the history-size and 50-pin limits (pins may hold at most 24 MB, `pinByteBudget`, leaving history room), and tells "nothing to import" apart from "couldn't read". Auto-delete runs at launch, when its setting changes, after an import and on each copy. OCR runs one image at a time on a bounded worker, newest first, and drops results for deleted clips. The 50-pin limit covers snippets and collections and is shown where you act. Settings shows storage errors under Keep history after quitting. `SecureStorage` never replaces a storage key it can't read (file or keychain): saving fails closed and the key is kept.

A picture's menu offers Save Colors (`folioSaveColors`): its dominant colours (`FolioPalette.dominant`: 3-bit-per-channel boxes of a 96-pixel thumbnail, the fullest first, none closer than a set distance, up to five) read on one utility worker. Search reads the hex, the colour's name and its source.

Each file they hold is read once per modification date on one utility-priority worker, one file at a time: a picture's text (`VNRecognizeTextRequest`, accurate, from a 2048-px ImageIO thumbnail) and what it shows (`VNClassifyImageRequest`, labels with recall 0.01 at precision 0.9, up to six), a PDF's own text (the first 60 pages; for a scan, its first three pages read as pictures), a text file's first 64 KB and a link's address. ### Timers and Focus
- A pool of `TimerService.poolSize` (8) slots (keys `timer`, `timer2`…`timer8`), in `AppServices.allTimers`; `AppServices.startTimer` takes the first free one, and `TimerPool` observes them together. Home's Timer widget (`NookTimerWidget`) watches the pool and shows the running timer with the least time left, else one showing its done state, else slot 0, and its buttons act on the one it shows. Each slot keeps its colour (`tintIndex` into `TimerService.palette`; the default is its own slot, so the first three are orange, cyan and pink); a timer's `showsInNotch` and `focus` go when it ends or is removed.
- Timers page (`TimersAppView`): the title and count with the Focus and Notch chips (`timers.nextFocus`, `timers.nextHidden`: Focus is how the next timer starts; Notch shows or hides every running timer beside the notch at once and is how the next one starts); lengths (the presets plus 1 and 45 minutes, and Custom in a popover); then a card per running timer, up to three across, a row or two sharing the page's height so nothing is left empty, and past two rows they scroll (`TimerCard`: ring, time, editable name, then colour, eye, moon, When done, pause, +1 and remove, all the same 22-pt square, `TimerControlStyle`; one row is `large`, the time inside the ring).
- Beside the notch: only timers with `showsInNotch` count (`NotchViewModel.runningTimers`), soonest first. Beside the camera they're rows of bubbles (`timerItems`, `timerSides`, `timerLaneWidth`): the first finished timer as a pill, any others as ticks, running ones as bubbles spinning out as they arrive (`TimerBubble`), at most `TimerRow.maxBubbles` then a "+N" bubble, nearest the camera first. With nothing else showing they alternate around the camera, the soonest left and the next right (`TimerRow.alternate`, and `ClearBubbles` gives them both sides); beside a song they stay left of its cover, two and the "+N" (`TimerRow.besideSong`); beside any other activity they keep one side. `NotchViewModel` watches every timer's `showsInNotch`, `isRunning` and `finishedAt` and calls `timerRowChanged`, so a card's eye takes effect while the Nook is open. Settings → Activities → Running timer off hides all of it.
- A finished timer (`TimerService.finishedAt`, in the `.timer` activity, hidden or not) stays until the pointer hovers the notch, the Nook opens or `TimerDone.duration` (10 minutes) passes (`acknowledge()`). ### Voices from recordings

- Settings → Tsukumo → Voice, the Voice card (`VoiceSettings`, `RecordedVoicesSettings`): the models and a link to Studio, where everything else is (the agent's voice too): Siren's voice cloning with a simpler face. It needs Apple silicon and macOS 15 (`RecordedVoiceSupport`); elsewhere the section is one line saying why, and Automatic, the Mac's voices and Personal Voice work as before either way.
- **Models** (`VoiceModel.catalogue`): Finding voices (Sortformer v2.1 and WeSpeaker ResNet34, needed to sort recordings, with DeepFilterNet 3 for noise reduction, 288 MB in all), Music removal (SAM-Audio small, Meta SAM License, 1.2 GB, its own optional download because of its size; `VoiceModel.musicRemoval`, which never speaks), then Siren's three engines: Standard (Qwen3-TTS 1.7B, 3.1 GB), Standard (small) (Qwen3-TTS 0.6B, 2.0 GB) and Expressive (CosyVoice 3 0.5B with CAM++, 2.3 GB). Each row has its size and Download (Resume for a part-way one), then Use and Remove. A model's `extras` (DeepFilterNet for Finding voices) download with it but aren't needed: an install from before they were added stays downloaded and sorts without them, and its row shows Update, which fetches only what's missing (`VoiceModelStore.lacksExtras`). DeepFilterNet's repository keeps each version in a folder, so it's fetched by its README (`requiredExtension: "md"`, Siren's way) and loaded from `v3`. Nothing is on disk until Download; downloads come from Hugging Face into Application Support/MacSpaces/Voices/Models, a Hugging Face cache laid out as mlx-audio-swift expects, and a `.macspaces-complete.json` marker records each whole repository so models load offline (`VoiceModelStore`); the Hub's own copy of a repository is deleted once it's whole, so a model takes its listed size. Remove deletes a model's folders, keeping parts another downloaded model uses. Replies use the engine chosen with Use (`voices.engine`), else the closest copy downloaded that fits 40% of the Mac's memory (`VoiceModel.speakingEngine`).
- **Recordings in**: in Studio's Voices, drop audio files, or videos with sound, several at once, or +. They're only read, never copied; the list (path, name, state, people found, why it failed) is Voices/recordings.json, and one being sorted when MacSpaces quit waits again. Each is sorted on its own, one after another; a recording already sorted isn't sorted again. Recordings left waiting at launch wait for Sort. Before macOS 26 bringing them in is when Speech Recognition is asked for (the clips' words are written down on this Mac); macOS 26's transcriber needs no permission. Removing a recording takes its clips from voices still waiting (a voice left with none goes); approved voices keep theirs.
- **Record My Voice** (Siren's guided take: its `Recorder` and `ReferenceBuilder.build(from:script:)`): you read `OwnVoiceTake.passage` (Siren's Natural passage, about 18 s, so it fits one 20 s clip; pure in `Sources/Core/Voices`, checked by `check-voices`) aloud. The microphone is asked for only when Record is pressed; denied, the card says to allow it in System Settings. `OwnVoiceRecorder` records mono 48 kHz 16-bit WAV with `AVAudioRecorder` into Voices/Sorting/Takes/<id>.wav (never anywhere else), metering at 30 Hz on a `.common`-mode timer (Siren's level, -50 dBFS to full scale, eased; `OwnVoiceTake.level`), and stops on its own at 60 s. Use This hands the take to `RecordedVoices.makeOwnVoice` (before macOS 26, Speech Recognition is asked for then, as for recordings brought in), which sends it to the helper's `prepare` call (`TakeRequest`, `VoiceSorter.prepareTake`), the same path a sorted person's clip takes: decoded to 24 kHz mono, fingerprinted with WeSpeaker, Siren's light noise reduction over the whole take when DeepFilterNet is downloaded (the take as it was kept instead when it's clearly more like you, `ReferenceChoice.keepsOriginal`), cut on word boundaries with what was heard (`build(from:script:)`: the passage marks it a guided take and is never put in place of words the recogniser couldn't confirm, so a take whose words can't be made out says so), then measured for evidence (background gap, likeness, longest pause, fitness). The app judges the clip by Siren's sample checks (`OwnVoiceTake.problem`): under 8 s of clear speech, or speech under 20 dB above its background, fails with a one-line reason and Record Again. A take that passes becomes a new voice named My voice (renamable in its row), `consent` "mine" and approved (recording it is your own say-so), its one clip from "Recorded in Studio". The take and the helper's working folder are deleted whatever happens, and Voices/Sorting/Takes is emptied at launch.
- **Sorting** (`VoiceSorter`, in the helper): each recording is decoded and analysed by Siren's `SourceProcessor` (SoundAnalysis leaves out songs and music, Sortformer says who talks when, WeSpeaker fingerprints group pieces into any number of people), then people are joined across recordings (`VoiceGrouping`: complete link at 0.75 cosine, two people of one recording never joined). For each of up to eight people, their stretches without coughs, laughs or anyone else, in each of the (at most eight) recordings they're heard in, are checked to be only them and ranked (long enough first, then checked, then how far speech sits above the background); each recording's best and then the best of the rest, up to ten (Siren's `maximumCandidates`), are transcribed and cut on word boundaries (`ReferenceBuilder`). **Short bursts** (Siren's, `VoiceBursts`, pure in `Sources/Core/Voices`): when none of a person's clips reaches 8 s, each recording's clips are joined in the order said, a quarter second apart, into clips of up to 15 s (`ReferenceBuilder.joined`: all their words, scored afresh, loudness and liveliness averaged by length, the pieces deleted), and their note says so. Each clip is then fingerprinted and ranked on its fitness (`ReferenceFitness`) plus half of how much more it sounds like the person than their typical clip (Siren's likeness ranks, `VoiceSamples.likenessRanks`), and the best becomes their clip. **Deliveries** (Siren's, `VoiceDelivery`, pure in `Sources/Core/Voices`): with three or more clips within 0.12 of the best rank, the slowest and quietest of them (words per second plus loudness, as z-scores among them) is Slow and Soft and the quickest and liveliest (pace plus liveliness) Upbeat, each kept beside the person's clip (person-N-soft.wav, person-N-upbeat.wav, `Person.deliveries`) unless it's the Natural clip again; the others are deleted. **Cleaning** (Siren's, `SourceProcessor.clean`): the chosen stretches of each recording are read with a second of context either side at 48 kHz. **Music removal**, when downloaded: a stretch whose gaps between words sit within 30 dB of its speech (`MusicRemoval.gapLevelDB`, 5th against 90th percentile of 20 ms frames; music 10 dB under talk measures about -15 dB, a clean recording -60 dB) goes through SAM-Audio with the "speech" prompt (T5 features embedded in `SpeechPrompt`, so T5 is never downloaded; 4 Euler steps, 25 codec frames decoded at a time, overlapping 24 s pieces joined with a short crossfade, `MusicRemoval.overlapped`), and the split is used as a time-frequency mask on the original sound (`masked`: speech over speech plus residual power, never below -40 dB), so the voice keeps its own detail; it's kept only when SAM put at least -18 dB of the energy into the residual (`MusicRemoval.foundMusic`), else the stretch stays as it was. SAM-Audio loads only for this step, once per recording, and is let go before anything else loads. **Noise reduction**, when DeepFilterNet is downloaded: every stretch then goes through DeepFilterNet 3 (loaded once per recording, let go after), its attenuation capped at 12 dB (`capped`, a dry mix). Then back to 24 kHz; the cleaned stretch is transcribed, and the same words cut from the recording as it was replace it when they're clearly more like the person and no noisier (`ReferenceChoice.keepsOriginal`: 0.05 more alike, and 25 dB clear or within 2 dB of the cleaned clip's background gap). Talk over music is kept as talk when finding people (only songs and music on its own are left out), so with Music removal those stretches give clean clips. Without either model, or if cleaning fails, the recording is used as it is. Siren's singers aren't ported. The decoded copies are deleted at the end. Each recording is a sort of its own into Voices/Sorting/<recording id>, emptied once its people's clips are moved into their voices. **Joining** (`VoiceSamples.joining`): each person found joins the voice they already are when every fingerprinted clip of it is at least 0.75 alike (complete link), never a voice with a clip from the same recording; otherwise they become a new voice waiting to be approved. Clips joining an approved voice start left out, so it reads as before until you include them.
- **Voices** (in Studio's Voices): a voice (`RecordedVoice`) is Voices/People/<id>/voice.json (name, whose it is, `approved`, its clips as `VoiceSamples.Sample`: file, words, length, delivery, included, fingerprint, recording, evidence, pinned) beside its clips' WAVs. Approve asks whose voice it is (Mine, or Someone else's who said yes; Cancel changes nothing), kept as `RecordedVoice.consent`; only approved voices read, are listed in Studio's voice menu and the agent's voice menu as `recorded:<id>` (`studio.voice`, `wisp.voice`), or speak. **Which clip reads** (Siren's, `VoiceSamples.reference`, pure): each delivery reads one included clip of it, never joined ones at reading time: the one pinned with Use First (`Sample.pinned`; Choose Automatically lets it go), else Siren's preferred clip (`isPreferred`): identity safety first (a clip whose checks fell back, or measured under 0.60 like the person, comes last), then the sample checks (`passesChecks`: speech 20 dB or more above its background, one stretch of 8 s or more, not joined bursts, no pause between words over 0.6 s; anything unmeasured counts as a pass), then how complete its evidence is, then likeness less small penalties for background, fitness and a clip under 4 s, then fitness, likeness and background; of equals, the earlier clip. A delivery with no included clip reads Natural's choice, and a choice measured as unlike the person gives way to a clip that's them. So a short-burst voice reads its joined clip only when no single clip passes. **Evidence** (`VoiceSamples.Evidence`): sorting stores each clip's background gap (`ReferenceChoice.backgroundGapDB`), its own fingerprint's likeness to the person, its longest pause between words, whether it's joined bursts, its fitness, and whether a check fell back. Clips from earlier versions have none: the first time such a voice reads (more than one included clip, saved with clips), `RecordedVoices.measureClips` measures them once, the gap, longest quiet (`longestQuiet`, standing in for word timings) and joins (`looksJoined`, a fifth of a second of exact silence) off the main thread from the WAVs, and likeness to the voice's fingerprint through the helper's `likeness` call when Finding voices is downloaded, then saves voice.json; a Use First made before (`inferredPin`: the first clip is Natural and came from a later recording than another Natural clip) becomes a pin, so that clip keeps reading. Same Person moves the other voice's clips into this one (an approved voice is always the one kept, and the agent and Studio follow it); Not the Same Person moves a clip out into a new waiting voice. Remove Voice deletes its folder (an error says so if it can't) and returns the agent and Studio to Automatic if they used it. **Carried over**: voices saved under 4.00 and 4.01 (voice.json without clips, clip.wav with soft.wav and upbeat.wav) read as approved with those clips, unchanged on disk until edited; people found and not yet named (Voices/Sorting/found.json) become voices waiting to be approved, their clips moved into People, and the old list goes once every clip has moved. The Settings Voice card keeps the models, in a drawer (`settings.drawer.recordedVoices`, closed unless opened or a download runs), and Open Studio with how many voices there are and wait (check renders `check-voices-*` show it closed, empty, and with models, a download and voices, `MACSPACES_DEMO_ONLY=voices`).
- **Speaking**: with a tagged voice chosen and an engine downloaded, `WispVoice.speak` hands the reply to `RecordedVoices.speakAsAgent`; the helper renders the whole reply to a WAV in the temporary folder, which plays and is then deleted. If it can't (no model, an error), the system voice says it. Studio's takes use the same path.
- **The helper** (`MacSpacesVoiceHelper`, `VoiceHelperProtocol`): an XPC service, so MLX and the models never load in the notch app. Standard (Qwen3-TTS 1.7B, 8-bit) peaks at about 4.2 GB (its weights alone are 3.1 GB; measured with `Scripts/compare-siren.sh` on three 13–16 s reference clips, Fast and Best Quality alike); sorting stays near 1.2 GB (DeepFilterNet loads only between finding the people and transcribing their stretches; Siren measured its noise step at 0.65 GB), and about 3.2 GB while SAM-Audio removes music (measured with `Scripts/compare-siren.sh --hub` on two 75 s readings with a piano bed 12-15 dB under the talk: 3.1-3.2 GB, sorting in 19-26 s instead of 2-3 s; Siren measured 3.2-3.5 GB and about 0.38 s per second of stretch), loaded alone and let go before noise reduction and transcription. What keeps it there: MLX's buffer cache is capped at 128 MB while speaking; Best Quality's attempts decode in the same 0.6 s chunks as speaking (the decoder's working memory grows with the chunk, and 4 s chunks went past 6 GB); the reference clip's encoder runs in 2 s pieces with 0.32 s of context (the same codes as one pass); and the speech tokenizer's conv weights are laid out in row order once on loading, not copied by every convolution. It starts with the first request, runs one job at a time (download, sort, prepare for Record My Voice, speak, or likeness, which only `Scripts/compare-siren.sh`'s harness asks for; Stop cancels), lets go of the voice model before sorting or preparing a take, and exits after two idle minutes or when MacSpaces lets go. Requests carry the Voices folder's paths, so Debug harnesses (temporary Voices folders) never touch real ones. It never downloads except for Download, and never asks for a permission. Bundle: the helper adds about 28 MB to the app (a stripped 26 MB arm64 executable with MLX linked in, and MLX's 2.4 MB Metal library), about 11 MB compressed.

### Notes

- Storage: `NoteRepository` (`notes-v1.json`, at most 2,000 notes, 256 KiB a note and 16 MiB in all), reached only through `NotesService`. There is no hard delete: a deleted note is a revision with `deleted` set. A save whose base revision is no longer current keeps its text under the note's `conflicts` (Other versions), including deletions, instead of overwriting.
- Editors hold a `NoteDraft` (text, base revision, last saved text). `NotesService.commit` saves a changed draft through `save(_:text:base:)` and reloads it, so after a stale save the editor shows the current version and the typed text is one entry in Other versions. An untouched draft saves nothing.
- Page (`NotesAppView`): the list column has the title and New, a search field (hidden with nothing to search), the notes, and at the bottom a small Recently Deleted entry, shown only with deleted notes, that becomes Back to Notes. The editor's row has the status, Restore in Recently Deleted and one "…" menu with Delete and, when there are any, Other versions. Recently Deleted's editor is read-only, and "…" shows there only with other versions.
- Saving: 1 s after typing stops (a `Task`, cancelled by the next keystroke, a save, a note switch or a delete), on leaving a note or the page, and on quit (`willTerminateNotification`). A failed save keeps the text and shows the error on one line. While the draft is unchanged, the page follows edits from elsewhere (the widget, Wisp, another screen's Nook) and moves on if its note is deleted or restored there.
- Staying open: the page sets `NotchViewModel.isPageEditing` while the editor or search has focus, or while its menu is tracking (`NSMenu.didBeginTrackingNotification`), since the menu can reach below the Nook. It releases it on disappear.
- Search matches title and text, ignoring case. The body reads only a `Set` of matching ids (`matches`, nil with no query); `StoredNote.ids(matching:in:)` reads the text in a detached task 120 ms after the last change, cancelled by the next one, and reruns when the notes change.
- Widget (`NotesWidget`): shares `NotesService.trash`, `restore` and `NoteVersionsMenu`, which saves the editor before restoring a version.

### Tape
- Windows side by side in a strip you scroll, in the same process, off for everyone until turned on: from the Tape switch in the MacSpaces menu, Settings → Tape, the welcome guide's Tape page, or Find Action's Turn On Tape (beside How to Use Tape, which opens that page). `TapeFeature` owns the switch (`tape.enabled`). While it's off there's no `TapeController`, status item, observer or hot key, nothing is asked for and nothing goes in a dock or on Home; only `isOn` is read at launch. Debug harnesses never start it: `TapeFeature` works only under the real bundle identifier.
- **Turning on**: the first time, `TapeSettings.importOnce` copies what's valid of `gap`, `edgeGap`, `centering`, `reduceMotion`, `layout.sharedWidths`, `apps.policy`, `apps.paths` and `displays.disabled` from the separate app's domain (`dev.opensource.Tape`, read only), then sets `tape.imported`. It then creates the controller, `TabOverlayManager` and `TapeStatusItem`. Accessibility is asked for only from the switch (macOS's prompt) or the Allow Accessibility button (the prompt and System Settings), never at launch or on opening the page; `TapeFeature` looks every two seconds while it's missing and starts Tape when it's granted.
- **The separate Tape app**: while it runs this copy holds off, because two would move the same windows. The card says so and offers Quit Tape, the only thing that quits it; when it ends, Tape starts. If it launches while Tape is on, Tape pauses and waits the same way.
- **Menu-bar icon** (`TapeStatusItem`, `TapeMark`): created on switch-on and removed on switch-off, separate from the MacSpaces menu: status, Pause and Restore Windows, Go to Window, column moves, Width, Stacks and Tabs, Move to Display, Float, Managed Windows, Settings (the page) and Turn Off Tape. No updates, no Quit and no ellipses.
- **Turning off and quitting**: `TapeController.shutdown` puts windows back, at most 9 s. The icon and tab strips go at once and the switch waits; then the controller is released. `AppDelegate.applicationShouldTerminate` waits for the same when Tape is on, and otherwise quits at once; the stored switch stays, so Tape comes back with MacSpaces.
- **Shortcuts**: ⌃⌥ with arrows, H, L, Home, End, [, ], 1 to 9, W, comma, period, T, =, −, D, C, F and P, listed on the Keyboard card. MacSpaces' direct page shortcuts win (⌃⌥T Tray, ⌃⌥D Studio's Dictate): `NookHotKeys.register` has Tape let go while it registers. What Tape can't get is listed as unavailable on the card, and the menu doesn't show it.
- **Per desktop**: the Desktops card lists each display's desktops from `SpacesMonitor`, with the number, the name the Spaces widget uses (`spaces.names`, saved on Return or leaving the field) and a Tape switch; `AppServices` adds Spaces demand while Tape is on. Off desktops are stored by Space uuid in `tape.spaces.disabled`, so a new desktop is on. Each scan reads the list itself on its worker (`ManagedSpaces.read`, passed through `WindowServer.scan`), because `SpacesMonitor`'s reading waits 0.45 s for a swipe to settle. `TapeController.isDesktopOn` (`SpaceLayout.isShowingDisabled`, by display UUID or the one "Main" entry; a full-screen space or a display not listed counts as on) gates `consume`, `perform`, `scroll`, `relayout`, `updateScrollTargets`, sending a window, and what the menu and the card offer. It's kept apart from `isEnabled`: `restorationFrames` and `applySettings` still treat these windows as Tape's, so pausing or quitting puts back a window arranged on a desktop since turned off. `consume` restores windows it sees on an off desktop that Tape arranged (`restoreWindowsOnOffDesktops`). There's no map of which window is on which desktop, so turning off the desktop showing takes effect at once and turning off another takes effect when it's next visited. The icon stays visible, and the menu says Off on This Desktop. Without the private list nothing is off and Tape runs everywhere.
- **Which windows**: a window joins the strip only if it's a normal window (`WindowDiscovery.isNormalWindow`: the standard subrole, or no subrole with a title bar's close or minimize button, since apps' popups and panels report none and have neither), can move and resize, isn't minimized, full screen, MacSpaces' own, showing a sheet, modal (`AXModal`), fixed size (a known app, or its zoom button disabled) or under 260×160 (`WindowDiscovery.smallestTile`) (`WindowTraits.isTileable`). A window already in a strip is never dropped for its size (`WindowSnapshot.tiledAtAnySize`), since Tape's own layout can make it small; columns are never narrower than `WindowDiscovery.smallestTile`'s width. Pausing clears the tab strips, and resuming draws them again.
- **Motion**: windows slide to their places over `Animator.slide` (0.22 s, ease-out cubic), on the display's own frame clock; a new move mid-slide starts from where the windows are and takes what was left (at least 0.04 s). Sizes change at the start of a slide, so an app lays out once. Reduce Motion places them at once.
- **Tabs**: a stacked column's tab strip (`TabOverlay`, a nonactivating panel) is in the theme: the Nook's surface with a hairline edge, each tab its app's icon and the window's title, the active one in the accent; click to bring a window forward, drag to reorder.
- `TapeAppList` lists apps for Managed Apps on one utility worker, a newer list replacing an older one. Permissions lists Accessibility as used by Tape while it's on (`PermissionKind.usedByFeatures`). Settings live under `tape.*` in `WidgetOptions.Keys`, with Tape's own defaults; the log is `Application Support/MacSpaces/Tape/Tape.log`, events and errors only, never window titles.

### Spaces
- `SpacesMonitor` (`AppServices.spaces`, service "spaces") runs only while Desktop changes is on, Home shows the widget or Tape is on. `NSWorkspace.activeSpaceDidChangeNotification` says when to look; `SpacesMonitor.settleDelay` (0.45 s) after the last one, so the swipe has landed, it reads the list on a utility queue. The widget appearing and displays changing read it too (a desktop added or removed posts nothing); stopping drops a read under way. No permission.
- The list is private and optional: `CGSCopyManagedDisplaySpaces` and `CGSMainConnectionID`, found with `dlsym` (`ManagedSpaces`). `SpaceLayout.parse` (pure, in `Sources/Core/Spaces`, checked by `check-spaces`) turns its answer into each display's desktops in Mission Control's order; only `type` 0 spaces are desktops, numbered per display from 1, so a full-screen space has no number and, showing, no current desktop. A missing symbol or any unexpected shape sets `isUnavailable`, until a later read makes sense: the toggle, gallery card and Add Widget entry hide, and a saved tile stays saved but takes no room on Home. Nothing else changes.
- A screen finds its entry by its display UUID (`SpacesMonitor.identifier(of:)`, `NotchViewModel.displayIdentifier`); with Displays have separate Spaces off the one entry, "Main", covers every screen.
- Widget (`SpacesWidget`, `.spaces`, small): a dot per desktop on this display (`SpaceDots`, eight to a row, the current one in the accent; pointing at another shows its name below, clicking goes there) and the current name under it ("Desktop 2" with none, "Full screen" on a full-screen space). Clicking the name opens a popover listing every desktop on the display (`SpaceNamesEditor`, each field at most `SpaceLayout.nameLimit` characters), focused on the current one: Tab moves down, Return or clicking away saves them all, Escape cancels, and an empty name forgets that one. Names are kept by Space uuid in `WidgetOptions.Keys.spaceNames`.
- Going to a desktop (`SpacesMonitor.jump`) presses the user's own Mission Control shortcut, because macOS has no public way to switch and the private call leaves the Dock out of step. `SpaceLayout.shortcuts` reads `AppleSymbolicHotKeys` from `com.apple.symbolichotkeys` (an entry missing, or on with no keys, means ⌃← and ⌃→ for moving and off per desktop). `SpaceLayout.jump` uses Switch to Desktop N when it's on and there's one display (those numbers span displays), else Move left or right a space that many times, `jumpStepDelay` (0.15 s) apart, counting full-screen spaces. Those act on the display under the pointer, which is the clicked one. The click asks for Accessibility, the only part needing it; while it's missing, or the needed shortcut is off, `SpaceJumpHelp` says so in a popover with a button to the right settings page.

### Weather, Calendar, Battery and Bluetooth
- Weather demand comes from its widget, visible page and bounded dock warming; Open-Meteo with an IP-location fallback. The page's location label is a menu (`WeatherPlaceMenu`): Automatic (the default), your Clock places, or Search for a City (`WeatherPlaceSearch`: zone.tab, then Apple's geocoder); a chosen place is `weather.place` in the Clock's place format, sends only its coordinates to Open-Meteo, skips Location and the IP lookup, and keys the forecast cache. Use My Location shows only while Location has never been answered, and asks. A versioned forecast cache in the app cache directory is read/written off-main, retaining matching-unit conditions up to six hours across launches. Reopens reuse forecasts under 15 minutes old; scheduled 15-minute polls force refresh. Pages and widgets never request Location; without it Weather uses IP location until allowed from Settings → Permissions or Try Again. There is no duplicate hover-details popover.
- Calendar via EventKit; the year progress and month grid follow Aaron Lichtman's DayDrop. The page's top corner switches Calendar / Life (`calendar.showsLife`). Life (`LifeView`, maths in the pure `LifeProgress`; designed by Codex): the birth date, age and percent of the span over the thin bar; the weeks as two banks of 52-dot rows grouped by decade (lived in ink, ahead faint, this week in the accent with a ring), with this week, weeks lived, weeks left, weekends left and birthdays left beside it; no key or explanatory copy. The Calendar/Life switch sits top-right on both views; Open Calendar is beside the agenda date.
- The Battery widget and visible System page start Bluetooth monitoring: paired-device reads plus the macOS connected-device report when IOBluetooth omits accessories; battery reads cached 30 s, connection fallback every 4 s; unknown stays unknown; earbud and case levels separate. Power uses the internal battery's capacity ratio and charging flag, not the presence of external power.
- Network use is limited to what features need; README's Privacy section is the public list (Open-Meteo, ipapi.co, Apple's geocoder for Weather and Clock places; LRCLIB, lyrics.ovh, Spotify oEmbed and Web API, iTunes, Deezer, YouTube; frankfurter.app; GitHub; Wisp's Anthropic, OpenAI or custom address; Hugging Face, only for a voice model's Download; the pages you save in Folio's Links, each read once). Keep it current when adding a service.

## Build, release and updates

- Bundle `dev.opensource.MacSpaces` (keep it stable for settings and update verification); team `28LJG7MXT3`; keychain profile `MacSpaces`. Never commit credentials, generated projects or release artifacts.
- Packages, pinned in `project.yml`: SwiftTerm (MIT; licence in `Sources/Resources/Acknowledgements.txt`), linked into the app; and, for the voice helper only, the local `Packages/SirenQwen` and `Packages/SirenCosyVoice`, mlx-audio-swift at Siren's commit, and mlx-swift, swift-transformers and swift-huggingface held at the versions Siren ships with (`Package.resolved` isn't committed). Every `xcodebuild` passes `-skipPackagePluginValidation` (Makefile, CI, package-release.sh). MLX compiles Metal shaders, so builds need Xcode's Metal toolchain (CI installs it when missing).
- The voice helper (`MacSpacesVoiceHelper`, an `xpc-service` target) is embedded at Contents/XPCServices/MacSpacesVoiceHelper.xpc. It is arm64 only (`ARCHS`, `EXCLUDED_ARCHS`) with a macOS 15 deployment target, while the app stays universal on macOS 13. package-release.sh signs it (hardened runtime, no entitlements) before the app.
- `make` builds Release locally. `make release` runs `Scripts/package-release.sh`: universal Release build, Developer ID signing with hardened runtime (the power helper first, with its own identifier), app notarization and stapling, DMG creation, DMG notarization and stapling (two rounds so both pass Gatekeeper offline; `notarytool --timeout 60m`), then signature, architecture and Gatekeeper checks on the mounted app.
- CI (`.github/workflows/ci.yml`, macos-26): all check scripts, plus a Debug arm64 compile check with cached Swift packages, built as the Feature QA harness so the `budget` scope runs on it, report only (a warning, not a failure) until it has passed three times on unchanged main; it runs on every push to main and by hand on other branches; a newer push to main cancels an older run, and a run started by hand is replaced only by another of the same commit. A passing local build is not enough: CI must pass on the exact commit being released. `feature-qa.yml` runs the Debug harness on GitHub's Macs when dispatched (see [CI, Feature QA and preflight](#ci-feature-qa-and-preflight)), uploading the captures; `Scripts/qa-clean.sh` then deletes the branch and its runs, so the Actions history is CI's release runs only.
- **Shipping**: bump `project.yml` and `RELEASE_NOTES.md` (current version only, named in bold), then run `Scripts/ship.sh` in the background with any commit trailer in `SHIP_TRAILER`. In order it:
  1. runs seven checks;
  2. makes a new root commit `MacSpaces X.Y` and pushes it with force-with-lease;
  3. runs `make release` while waiting for CI on the full commit SHA (`gh run list --commit` ignores short SHAs);
  4. tags `vX.Y` and runs `Scripts/publish-release.sh` (Latest; refuses development builds; adds one hidden `macspaces-build` marker);
  5. updates the Homebrew cask, then deletes every older release and tag, first adding each release's download count to `downloads.tsv`.
- **Downloads**: deleting a release deletes its GitHub download count, so `downloads.tsv` (repo root, git-ignored) is the only record of earlier releases' counts; never delete it. Counts before 3.17 were lost. `Scripts/downloads.sh` prints each release's count, the current release's live count and the total. The installer, Homebrew and the in-app updater all download `MacSpaces.dmg`, so the counts are downloads, not people: a release's count is roughly its new installs plus the installs that updated to it.
- `main` is a single root commit, `MacSpaces X.Y`, with no parent; each release replaces it. No recovery bundles, backup branches or spare app copies. A replacement installer for the same version updates that release.
- **Docs-only updates**: `Scripts/publish-docs.sh` replaces the root commit and moves the current tag, installer unchanged. It publishes `README.md`, `AGENTS.md`, `Demos/` and `docs/` only and refuses if anything else differs from the published commit.
- **Versions**: `CFBundleShortVersionString` is the public version (2.x used `major.build`, 2.32 … 2.100; from 3.0 plain names; 1.0.0 predates both). `CFBundleVersion` is an internal integer that must exceed every published build, since updaters compare builds. `check-release-policy` enforces this.
- **Updater** (`UpdateService`, `ReleaseRevision`): Checks run hourly and ten minutes after the Mac wakes. An automatic update downloads, verifies and installs at once, quitting and relaunching MacSpaces with no prompt and no wait; with automatic installs off, the update is offered (the menu-bar dot, "Update to MacSpaces X" first in the menu, Install on the Updates card) and installs when chosen. A copy outside /Applications fails before downloading, and a build whose install failed (`failedInstall`, kept until relaunch) is left alone by automatic checks; Check Now tries again. The update notification posts only when notifications are already allowed (it never asks) and says what will happen. Checks are skipped while an update is offered or on its way. **Anonymous count**: with Count this Mac on (`updates.countInstall`, on unless turned off: unset reads as on through the registered default), the count POSTs `{id, version}` to `https://macspaces.dev/api/ping` at launch, with each successful check (hourly) and at once after an update, at most every 50 minutes otherwise (`updates.lastCountVersion`; the site keeps IDs in a set, so repeats never count twice); `id` is a random UUID made once (`updates.installID`). The site (PORTFOLIO `src/app/api`) keeps the IDs in Upstash Redis and shows every count on one page, `macspaces.dev/stats` (installs, active today and in 7 and 30 days, by version, and downloads by release), behind a browser password prompt checked against the `STATS_PASSWORD` environment variable (without it the page is a 404). The only public count is the README's downloads badge at `/api/downloads` (shields.io release downloads plus `downloads.tsv`, which is in the repo).
  - 1.14 and 2.38+ read releases/latest; 2.36 and 2.37 read the release list and take the newest non-draft release of their major version (`ReleaseRevision.newest`).
  - Updates download automatically by default, look hourly while running and check GitHub once six hours have passed since the last check, download only over https from GitHub's release hosts (`isTrustedDownload`), and verify the app's version, build, bundle id, signing team (`signingTeam(fromCodesignOutput:)`), minimum macOS and architecture before asking to relaunch. A build this Mac can't run is remembered and skipped.
  - 1.14's updater can't check the minimum macOS, so the current release must keep running on macOS 13.
- **Homebrew**: `zlichtman/tap/macspaces` is the only cask (`depends_on macos: :ventura`; run `brew style zlichtman/tap/macspaces` before pushing the tap); `cask_renames.json` moves old `macspaces@beta` installs to it.

### CI, Feature QA and preflight

- **Preflight** (`Scripts/preflight.sh`, before every push or dispatch): one incremental Debug arm64 build of the harness as CI and Feature QA build it (`dev.opensource.MacSpaces.FeatureQA`, then `.WebsiteDemo`, which only relinks), then every `Scripts/check-*.sh`. Output goes to `~/Library/Caches/MacSpaces-preflight/<checkout>-<hash>` (outside iCloud; `--clean` removes it), with the Swift packages shared in `SourcePackages`. It refuses (exit 75) when `mac-status` shows free memory under 40% or swap over 6 GB, or another `xcodebuild` runs, and compiles with `-jobs 4`. A failed build prints its errors, deduplicated, and the checks still run. `--build` skips the checks. While the screen is locked it skips `check-notes`, whose notes file (`completeFileProtectionUnlessOpen`) can't be reopened then. Measured on the owner's 12-core, 18 GB Mac: from nothing 70 s (build 41 s) peaking at 3.0 GB for the whole process tree; after a one-file change 35 s (build 11 s) at 1.2 GB; 0.5 GB on disk per checkout.
- **Step causes**: every `run` step in both workflows runs through `Scripts/ci-step.sh` (`defaults.run.shell`), which keeps GitHub's `bash -eo pipefail` and, when a step fails, writes one line to the run summary and an error annotation, so `gh run view <id>` names it: the check script or `xcodebuild`, then the first compiler error (with a count of the others), else a Swift trap's message (with the lines it printed after a trailing colon, such as each budget overrun), else a timeout, else the last line. `Scripts/ci-step.sh --cause <log>` prints the same line for any log.
- **Feature QA** runs only when dispatched; a push starts nothing, so nothing is cancelled: `gh workflow run feature-qa.yml --ref qa/<name> -f scopes="agent-popout notch-looks" -f clips=readme-hero -f tour=nightBlossom` (`scopes=none` for clips or the tour alone). Every scope runs even when an earlier one fails, each with five minutes at most; the summary has a table of scopes with the result, time and cause (a scope that crashed without a message names its signal, and the first such scope is run once more under lldb, adding the first MacSpaces frame from the backtrace). Clips and the tour run whenever the harness built. Dispatches never cancel one another.
- **What gates a release**: CI on main runs only checks that give the same answer every run (the check scripts and the compile). Timing measurements, such as a performance budget, run in Feature QA as a scope and report there: on GitHub's shared VMs the budget failed on unchanged 3.29 code (passes up to 116 ms against a 33.4 ms limit), and one build measured twice in the same job saw the same pass at 126 ms and then under the limit.
- **Cleaning up**: `Scripts/qa-clean.sh qa/<name>` cancels the branch's running runs, deletes every run whose branch is exactly that one (CI and Feature QA, any outcome), then the remote and local branch (`--keep-branch` keeps it). It accepts only `qa/` names, so main's and the releases' runs are never touched.

**Side by side with Siren** (`Scripts/compare-siren.sh <recordings folder> [--lines <file>] [--output <folder>] [--engine <id>] [--siren-check <path>] [--siren-takes <folder>] [--hub <models folder>]... ### Local promotional captures

`Scripts/capture-demos.sh` builds an isolated WebsiteDemo app and records its clean window with ScreenCaptureKit, using the production Core Animation and Metal effects, real-time timing, no pointer and no audio. Other windows and the desktop are excluded by a single-window filter; the camera housing is a drawn stand-in because physical camera cutouts cannot be recorded. The real app and its preferences remain separate. Screen Recording permission is required for the capture terminal. Leave the desktop unlocked and the demo window visible; the script runs the sequence and closes it automatically. It refuses a locked desktop before building and keeps the display awake only for its own run. To check clips while the desktop is locked, run the built app with `MACSPACES_DEMO_RENDERED=1`: every clip is then drawn frame by frame into `clip-<name>` with no Screen Recording (and no Metal shaders, so those frames are for checking, never for publishing).

`Demos/music-sequence.json` holds the original five songs, excerpts, order and theme pairings recovered from the existing Music video. `Scripts/demo/prepare-music.py` resolves exact title/artist/album matches and uses the fixed excerpts and playback positions from the original silent video; a missing track, lyric or cover stops capture. Covers remain temporary, outside iCloud, and are deleted with build output on success. Failed runs retain their own build for `--retry --output <folder>`; `--clean --output <folder>` discards that temporary build without deleting exports. Both Feature QA and local capture use this manifest. The reel opens on Home's current Music widget, opens Music and moves through the original five pairings. Separate settled stills and a five-song proof sheet are generated automatically. No interpolation is used.

Run `Scripts/capture-demos.sh --check` for prerequisites, `--music-only` for the reel and five stills, or `--stills-only` for stills only (it records no video, so it never replaces one), or `--videos` for the hero reel, the Tour, Calendar, Clock, KemoSabe, Tape, Agents and Pop-outs videos and the Tools images, or `--test` for a few clips that go to the output folder only. `--output /absolute/folder` selects a new capture folder; the default is a timestamped temporary folder. The default run captures everything the site shows: the reels, every page still (with Heartable's `page-stats`, `page-backups`, `page-backup-compare` and `page-shelf`, and Folio's `page-folio-library`, `-board`, `-viewer`, `-search`, `-colors` and `-links`) and what `--videos` makes. It updates local website and README assets through `publish-demos.sh`, which never publishes a video under 20 frames a second (measured with `ffprobe`; a covered or throttled capture window records only a few), with the explicit Music poster taking priority; a file the site doesn't have yet is added only when `data.ts` declares it with `upcoming()`. Nothing is committed, pushed or deployed. Review `music-proof.png`, `site/` and `capture.json`; logs remain in the output folder. Temporary builds, covers and raw movies are removed automatically after successful export. Failed capture folders retain diagnostic output and a retry marker. `--all`, `--music-only` and `--stills-only` can also select the batch on a retry. Each launch uses fresh temporary fixture data and resets only the isolated demo preferences. The panel is pinned while captured. One reusable preview window, up to 820 points wide so the recording is never scaled up, sits at the right edge of the current desktop. It uses normal window level, stays on that desktop, does not activate or repeatedly raise the app, and never moves the pointer. The preview can be dragged by its background or covered by other work; the recorder selects only that window. The Debug lyric preview explicitly carries playback state, so native lyric animations run with the song.
